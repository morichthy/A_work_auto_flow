# 本地材料与阅读

已有上下文足够就先推进，需要依据时按当前问题和授权范围检索。Owner 是研究、项目、Run 等对象的稳定身份，不是 MEM 正文记录 ID，也不是可信等级。

## 主 Agent 与 reader

已有 RS 用 `reading-list --owner ID` 查找，主 Agent 通过 `reading-handoff --session RS-ID` 接收笔记，不先加载全部候选或历史。新问题用 `reading-template` 填写目标、条件、query 范围和本次任务 owner_id，再 `reading-start`。程序已从[工作区设置](../../../docs/WORKSPACE_SETTINGS.md)应用默认值，AI 不另读配置文件；新模板采用 owner_document，旧 RS 沿原模式兼容。精确字段按[AI 阅读接口](../../../docs/AI_READING.md)和模板填写，不猜参数。

复制模板/已有请求后只改必要字段，不重新手填整份query。scope筛直接候选，scope_ceiling限制获准必要依据；不要机械复制前者到后者，造成文稿引用的Run被误拦。依赖读取仍受已有授权与排除约束，不以空上限扩大授权。

需要阅读时主 Agent 调用 reading-delegate，填写宿主实际是否有子 Agent 工具。route=subagent 时须真正调用宿主派工工具，仅传工作区路径、worker_brief、RS/revision 和本 Skill，不继承主对话。按返回的能力要求选择可用模型；默认适当的低成本、较低能力和低推理，自定义要求优先。delegate 本身不启动 AI；关闭或宿主不支持则主 Agent 沿同 RS 执行。

同 RS 一次一位 reader，不递归委派；主 Agent 可做独立工作。reader 保存笔记与决定后，仅回 RS、revision、阶段和短缺口。主 Agent 通过 handoff 取得笔记用于后续工作，不增加固定的复检、复读原文或审核轮次；后续实际需要出处时再按引用读取。交接仍携带缺口和等待状态，交接完整不代表研究完整。

## 检索 → Owner → 文稿

先按模板或当前 RS 的 `strategy` 工作，不自行覆盖用户保存的默认模式。standard 是下述完整阅读流程；associative 在原问题未充分解决时，由主 Agent 根据已有 note 的缺口与材料线索制定具体子问题和关键词，保存 `association_text` 后交 reader 以 reading-recall 追加召回，再走相同的 Owner 全文阅读。reader 只执行给定搜索文本，不自行制定联想方向。用 reading-configure 显式切换当前会话，不能重置授权域、累计预算或等待用户的状态；工作台配置保存本身不启动 AI。

quick 只用实际交付的召回文本：对每个 candidate_id 调用 reading-assess，保存 useful 与 reason；需要更多片段时 reading-page。仅以接受的固定片段调用 reading-note，不调用 reading-read，也不补写未读全文的内容。未判断、缺必要定义或未覆盖部分明确作为缺口。之后切回 standard，必须实际读完文稿才能提交标准 note。

1. 根据获准语料语言准备少量等义查询；技术/文献问题即使中文提问也补英文关键词与完整英文句。原问题保留，型号、版本、数值/单位、范围、否定和工况不可改写。未知语料说明未知，英文不是可靠性标准。
2. reading-recall 填写语言计划与领域；最多三条去重等义查询（含原查询）。词法用紧凑术语，向量用完整句。程序按领域使用[术语库](../../../retrieval/query-terms.json)，冻结计划供 reading-page 续页；单跳关联只作探索，不当等义或科学支持。无需 AI 每次打开整个词库；维护词条时按[术语库手册](../../../docs/QUERY_TERMS.md)读取相关领域并保存依据。
3. 程序内部融合、重排和去重；每个Owner先交一段，AI只读正文与owner_id。尚不能判断时按has_more/pending_owner_count继续reading-page，不因首段无关就断言整个Owner无关。按问题核对相关性：可直接使用、有具体迁移理由的启发、冲突、未说明分别处理。字段条件由程序核对，复杂语义不因排名或pending而成立。
4. 确定 Owner 有用就 reading-read 指定 owner_id；后续跳过该 Owner 的其他候选。一次读一个 Owner 的现有文稿，优先完整研究过程。检查返回的实际文稿类型、固定版本、完整性和缺口；缺文稿的真实正文回退不称为完整研究报告，也不因同 Owner 就认定所有材料支持结论。
5. 图片、L0、Run 等内容多的材料先保留固定引用；需要解释图形、复算或核对原件时再沿已交付引用展开，不自动读全部原件。Run 的结论/限制可提供摘要；空结论或缺文稿应记缺口，不把原始日志拼成既成结论。

## reading note：简化研究报告

reader 在阅读过程中，围绕当前问题提取关键公式/定义、变量与单位、条件/假设、实验结果/反例及图示，把每项与实际交付的正文、Run、L0或图引用对应。这个对应关系用于组织笔记，不新增独立清单文件或交给主 Agent 的审核包。

实际阅读后按 Owner 保存 research_note。目标是一篇细节充分、可继续研究的简化完整文稿；下面的要素是覆盖要求，不是每栏一句的短摘要模板。understanding可以承载多段连贯正文，logic/details补足必要方法与实验细节，避免同一内容在各栏反复抄写。

按实际依据连接研究过程：最初遇到什么问题、已有方法为何不足、提出了什么假设、为何选择这些方法/实验、观察到了什么、失败或反例怎样促使认识修正、当前能得出什么以及下一步如何接续。说明材料明确记载的理由；自己的解释标为推断，缺失的历史不编造。只有一次实验或只有部分片段时按实际覆盖写，不强凑多轮故事；quick不能写成已经阅读全文。

以连贯段落解释因果和证据，把公式、参数及引用嵌入对应论述。并列比较、操作步骤或参数对照需要时再用列表/表格，不把研究经过压成数字目录。至少覆盖：

- 材料自身的研究问题、适用范围与条件，以及对搜索问题有用的知识；不重复当前搜索问题。
- 关键认识和与问题的连接；保留推理步骤、证据与假设，区分原文主张、实测、AI 推断和建议。
- 决定性细节：定义、主公式及误差公式、变量/单位、参数/输入输出、适用边界、反例和失败模式。公式用可读 LaTeX；递推保留初值和更新顺序，误差式说明成立假设；与任务有关的核心经验不得为凑预算丢失。
- 各项关键判断的固定出处与定位，必要时附图片、L0/Run 的地址或 ID；未展开引用明确为未读，不能声称已核验其内容。
- 材料的限制、缺失和待验证事项；有实际依据的材料建议可写在“可选的下一步建议”，没有则省略。不得写 reader 的下一步操作、派工理由、检索决定或执行结果。

reader 写完后在同一阅读任务内，对照上述相关内容核对：核心公式是否完整、变量/单位/条件是否保留、实验数字和图示是否有对应出处、反例与限制是否遗漏。发现缺项先补齐再提交；原文没有的内容明确写入limitations，不编造公式或引用，也不把不足转交主 Agent 作为例行审核任务。

阅读时主动留意能帮助当前问题的上游、下游、共同变量与可迁移机制；有实际线索时写入 exploration_clues 的 text、reason、sources、next_query、limitations。reason 说明材料为何构成线索，不记录 reader 的行动理由；next_query 只保留材料明确提出的问题或主 Agent 已给定的查询，未知留空。保留关系方向、变量单位、工况、时间或版本、证据类别和反例；原文没提供就标未知，不为填表猜测。没有具体线索可省略，不强求每份 note 都联想。主 Agent 据此决定后续联想问题和关键词；reader 记录实际给定子问题及 clue_sources，等义查询仍须匹配该子问题的条件。跨 Owner 新认识调用 reading-synthesize，区分直接依据与待验证的组合推断；底稿或依据变化后重新核对并更新综合 note。达到轮次/范围上限或无新有效依据就保留缺口停止。

sources可填read已交付的来源ID，由程序固定版本与指纹；有多版本歧义时程序化复制所选FixedRef，不手抄SHA或另猜路径。引用程序检查在reading-note保存时执行，不增加AI调用；结构与引用通过不证明语义完整。与任务无关的长例子可省，影响理解的省略须说明。

主要上下文控制由设置决定：最多阅读 Owner 数和最终 note 的估算 token 上限。内部搜索/路线诊断不挤占 note；工程超时和单次资源保护仍有效。note 整条交接，不切断公式或必要条件；预算是上限，不是越短越好的目标；先去重复和无关内容。若仍不足以保存关键研究过程和依据，明确容量缺口与所需调整，不把连贯文稿悄悄压成结论提纲。宿主 token 与自动压缩不由本项目保证；逐篇及时保存阅读进度和 note，同 RS 可续接，不用新 RS 逃避范围或阅读数限制。

## 决定、保存与恢复

reading-decide 保存实际理由和下一步：proceed 后先工作；相关但缺细节则按需读深；路线失败且经验仍可能缺失则改写/扩大获准范围；需要用户取舍才 ask_user，已询问须等真实意见，不伪造 human_decision。授权、排除和固定版本始终检查，程序诊断不进入主 Agent 的常规上下文。

note只保存与搜索有关的材料研究问题、知识、条件、经验和局限；不重复当前搜索问题，不写reader的派工、决定或执行结果。联想搜索文本/关键词由主Agent明确给出，reader只在授权范围内检索并保存材料线索。RS绑定任务Owner和可选检查点；笔记不是规范知识，可复用成果另按work-loop保存。

人类可读副本为 `context/reading-notes/<RS-ID>/current.md`，程序生成，不手改代替保存；使用当前来源仍经 handoff 重验。工作台首页与“系统记忆→阅读记录”共享选择，Owner 与 RS 分开显示。交接给出实际存在的副本与修订。

手动查询/旧表示入口见[材料查询手册](../../../docs/MATERIAL_QUERY.md)，不必先建 RS。旧记录模式的 read/note 字段见 AI 阅读接口兼容段；不要把新 Owner 请求套到旧会话。语义维护和结构关联按需独立使用。

## 展示副本与公式引用

recent/snapshot和`current.md`只用于展示；主Agent继续通过reading-handoff取得当前授权和固定来源核验后的内容。公式必须实际写为`$...$`或`$$...$$`；兼容`\(...\)`/`\[...\]`由渲染器处理，裸` s_i=...`不算已标记LaTeX。关键判断在对应正文就近引用固定依据，并与文末来源逐一对应；编号引用须保留对应FixedRef的ID、revision、hash和locator。历史正文只有记录级来源而无具体位置时说明缺口，不按列表顺序猜测句级或块级映射。
