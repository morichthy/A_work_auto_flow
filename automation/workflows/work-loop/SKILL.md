# 工作与记录

方法、拆解、阅读范围和验证强度由 AI 根据任务判断。用户指定优先；这是一套记录协议，不要求先选择研究或开发模式。

最近阅读副本与快照只用于展示；续接当前问题仍通过reading-handoff核验授权和固定来源。24小时recent窗口不删除历史，也没有后台时钟刷新。

开始任务或用户修改设置后，用 `workbench.cmd workspace-settings policy` 读取一次精简协作策略；不让AI逐次打开设置文件。`subagents=off` 时由主Agent独立完成，不委派；`auto` 仅在宿主提供能力且任务适合时使用，否则沿同一单Agent流程。派工按`subagent_requirements`选择宿主可用模型和推理深度，缺省偏向较低能力与低成本；自定义要求优先于缺省偏好，不扩展工具或材料权限。用户本轮明确要求优先。新检索由程序缓存配置生成模板，已有会话保留已定策略；Owner阅读以阅读数和最终note上下文为主要限制，工程保护与旧会话预算分别保留。具体调整见[工作区设置](../../../docs/WORKSPACE_SETTINGS.md)。

用 `memory list-owners`/`inspect` 找候选Owner，比较其目标、概览、已有成果和未解问题：本次是同一目标的继续或子任务就沿用；仅主题相似则引用，独立交付目标才另建。用户指定优先，目录名不是判断依据；持续任务用 `memory resume` 读必要目标与下一步。工具用于业务数据时，Run通常归业务对象；通用工具经验以固定引用归工具。源码、记忆和运行输出分开。

持续或多步工作维护一份用户可打开的Markdown工作上下文清单，优先复用本任务计划。记录目标/条件、当前与召回材料的链接和阅读状态、理解/经验及必要细节、尝试/缺口、下一步与补查理由；无RS也维护。重要材料、结果或方向变化及交接时更新，不逐条抄日志。首次建立和交接给出链接；位置与续接见公共动作参考。

需要本地依据时使用 material-query。standard/associative 从去重正文选择Owner后逐篇完整读现有文稿；associative 只在现有信息不足时，以受限的实际联想搜索文本继续召回。quick 只逐条判断实际交付片段并写明非全文覆盖，不读Owner全文。按需展开图片/L0/Run，写保留关键经验的研究式note；跨Owner理解可保存综合note，来源或底稿变化时需重验。潜在线索保存依据、条件、未知和下一步，不自动晋升为结论或关联。主Agent通过reading-handoff仅接收笔记与固定出处。关闭/不支持则沿同一RS单Agent执行。已有依据足够就推进，不为每条消息重复搜索。阅读会话绑定本次任务Owner；`material-query reading-list --owner ID`发现，`material-query reading-handoff --session RS-ID`精简交接；来源Owner与会话归属Owner分别表达，旧RS按原模式兼容。

阅读 note 只保存材料中对搜索有用的知识与研究演进，不重复当前搜索问题，不混入 reader 的操作下一步、理由或结果。有依据的材料建议标题用“可选的下一步建议”。联想问题和关键词由主 Agent 制定，reader 按给定文本检索并报告材料线索；行动决定保存在会话决定或总工作清单。

独立执行建立 Run，Python等脚本用 `run-execute`，其他工具或已有产物用 `run-register`。保存真实输入版本、结果与失败；无执行的分析可直接记录，不虚构Run。重要配置变化、关键反例等即使很短也值得留存。L0–L4、Run 和独立文稿正文在关键判断旁就近引用固定依据，与文末来源对应；历史缺位置映射时保留缺口，不猜测补号。

Run结束时填写已有conclusion与limitations，说明结果、适用范围和失败；还没有结论时明确未完成，不把日志当总结。需要可复用技术解释时保存绑定真实Run的L1并编入所属Owner文稿；Run原生总结、技术正文与L0产物各司其职，不逐层复制整篇内容。

有用内容按职责保存：L0原始依据、L1完整方法/分析、L2有依据的经过、L3可复用认识、L4介绍或阶段概览。缺层正常，不补空条目，不重复正文。原文步骤可作L1，文献记载的经过可作L2；注明来源叙述、AI推断或本次观察，不把原文主张当成亲自验证。总之可以适当扩展L0-L4的定义，使得当前的工作流中有价值的内容通过分级记录下来。

对话中产生有用中间内容即可自主保存并提交，无需等用户逐次要求；未复核认识保留其状态，待同步影响写入当前工作清单。用户要求记录重要结论/当前成果、阶段总结或交接，以及AI发现结果、反例、适用范围或方向实质变化时，调用 [整理更新当前成果](../consolidate-results/SKILL.md)：先完整读取当前概览与文稿，盘点上次文稿以来的相关记录变化，再维护内容、概览、章节和文稿根，全文回读并核对上下文。每次普通commit不强制收口；用户明确只暂存或限定范围时遵从。只有完成该Skill的实际检查才标明“本阶段完整成果已同步”，不能把局部保存当作整体同步。

用公共 `memory validate-draft`/`commit` 提交并固定回读，分别检查保存和索引状态；INDEX_PENDING时补索引，不另建副本。交接时保存结果、依据、未解问题和可执行下一步；Owner检查点是工作交接，RS只管阅读。文稿按实际阅读/交付需要编排，不要求每任务双文稿。

自主推进已授权工作；依据不足时结合材料相关性与下一步对本地经验的依赖，判断推进、读深已有依据、改写/扩大召回或换验证方法，并记下理由；具体按material-query。不按次数强迫中断，方向、成本或权限需要用户决定才询问。反馈给出结果与可打开记录链接，未知事实和验证范围明确保留。

首次调用不熟悉的接口时按需读[公共动作参考](../../../docs/WORKFLOW_ACTIONS.md)，不必全文加载。公司算法准入/文档核对见[专项参考](references/core-algorithms.md)；开发采用development-checks的影响检查。不要把专项参考变成所有任务的必经步骤。
