# 批量材料接入

从用户给定路径、用途和授权范围开始，按需读[材料接入手册](../../../docs/EXISTING_MATERIALS.md)。分批实际阅读、归组和固定来源，保留读到哪里、失败和下批起点；登记不表示已读或已验证。

先用memory list-owners/inspect找已有对象。缺稳定身份用adopt-owner；批量用ingest-preview查看重复、冲突与缺失，再ingest-apply。原文不改写，不依据目录名创造身份；公司核心算法须有公司文档准入依据，普通脚本归tools。

原件保留在获批位置，记录版本/指纹与章节定位。已有Run附件不再重复登记source；逐字导出用实际lines/chars定位，OCR说明原图与识别完整性。取得时间未知留空，不能追认历史版本。

各类材料按内容生成可检索的概览、方法、认识或有依据的经过；来源叙述和AI推断明确区分，不凑层。如果是外部导入的文件进行记录整理和存储时，记录的完整文稿需要是文档原文（切分L1的正文块，保证记录组装成完整文稿时和源文档相同）；且文档类的知识记录区分不同的版本，不要以不同版本的形式提交在同一个记录中（比如某个技术文档v1和v2版本需要建立两个独立记录，分配独立record_id）。每条新增/修订记录遵守[独立可读标准与Owner映射](../../../docs/RESEARCH_RECORDING.md#每条记录必须独立可读可以正确复用)：背景、条件、必要定义、关键事实和限制直接写在本条正文，不能只留附件链接或payload；形成记录的AI逐条脱离上下文回读。knowledge原文没有记载形成经过时不编L2，核心算法仍先核对公司文档准入。来源可追溯不等于原文每个字已进普通知识索引；导入后以正文独有词/用途问题核对可发现和固定回读，缺口如实报告。

普通保存和交接使用[work-loop](../work-loop/SKILL.md)及公共memory接口。来源新修订影响既有结论时用semantic-maintenance实际审查；不通过重算旧哈希消除差异。批次结构变化后refresh-index/validate，相关检索投影按真实变化更新；用户未要求时不创建后台维护。
