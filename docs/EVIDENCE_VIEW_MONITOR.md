# 证据查看与只读监测

现行说明核对日期：2026-09-17。工作台“证据与影响”统一承载选中条目的详细阅读；独立 `evidence-view/evidence-monitor` 沿用原业务证据图与观察语义。

统一入口：运行 `workbench.cmd`（注册后 `rdwork`），一键进入证据、单次检查、持续监测和环境检查。合成数据演示使用 `workbench.cmd workbench --demo`。安装、迁移与命令注册见 [一键部署手册](SETUP_WORKBENCH.md)。本页保留独立 CLI 和证据语义说明。

“证据工作台”用浏览器展示当前记录，回答为什么保存、依据在哪里、谁确认过、何时发现失效，以及哪些报告引用它。它读取现有文件，既不需要安装前端依赖，也不需要向量模型或 OCR。

工作台可按标题、结论或ID搜索 Run、Owner、规范记录和文稿；系统记忆保留记录摘要，点击进入同一证据详情。L0展示材料与出处，L1展示方法和技术正文，L2展示研究经过，L3展示经验与适用条件，L4展示整体概览；Run分开输入、配置、执行、结果与限制，document按固定章节与技术块展开。CLI的 `memory inspect/history/source-lineage/impact/document/document-impact` 继续可用。监测候选不会自动写成对象记忆或完成文稿更新。入口对照见 [记忆指南](MEMORY_USAGE.md)。

## 日常使用

直接告诉 AI：“打开证据工作台”“检查这条结论的依据和受影响报告”“检查上次以来的材料变化”。常用入口是 `$evidence-inspection`；新会话尚未发现时，可让 AI 读取 `automation/workflows/evidence-inspection/SKILL.md`。

在工作区根目录运行：

```powershell
# 打开一个本机只读服务，访问终端实际返回的 URL；Ctrl+C 停止。
.\automation\workspace.ps1 evidence-view --serve

# 也可生成离线 HTML，用浏览器打开输出路径；重新运行才更新快照。
.\automation\workspace.ps1 evidence-view

# 预览本次监测，不写入任何基线或日志。
.\automation\workspace.ps1 evidence-monitor --dry-run

# 执行一次监测，保存本机观察记录及待处理候选。
.\automation\workspace.ps1 evidence-monitor
```

本机服务默认自动选择端口，也可加 `--port 8765`。仅监听 127.0.0.1，路径包含每次启动新生成的临时访问令牌，不要把该 URL 当跨机器永久地址。网页刷新只重新读取当前证据，不启动监测或后台写入。离线快照的来源预览不可用，可按显示路径在本地打开原件。

## 页面怎么看

搜索可按标题、ID、结论、保存理由、范围或复核人匹配；筛选对象类型和状态。选择一条记录后：

| 页面内容 | 含义 |
|---|---|
| 为什么保存 | 优先读取可选 `record_reason`；没有则展示所属记录的问题并注明来源，两者都缺则显示未记录 |
| 依据在哪里 | 已登记的证据引用、具体定位、固定指纹与当前版本是否一致 |
| Run 的输入与产物 | 已登记的执行证据文件，可展开及预览；它们不会自动变成已复核的结论 |
| 谁确认过 | 当前复核主体、原因、依据、时间与历史事件 |
| 何时失效 / 当前限制 | 当前风险、正式条件缺口、记录中的撤回时间；监测首次观察时间单独标注 |
| 哪些报告需要关注 | 沿 supports/input 等实际依赖找到报告；包括报告内部 claim 的依赖，显示关系路径 |

独立旧证据页的文本预览最多读取前 64 KiB；截断预览不能当作全文。工作台 `evidence/search` 查询本地元数据，`evidence/detail` 按固定ID、revision、hash、locator读取选中正文、上下文、引用与影响。登记图片按当前权限、安全路径和固定指纹读取后展示；文档/图片不可用时明确说明，不换用其他版本。普通 `metadata_only` 详情不代表原件或科学结论已经复核，图片字节核验也不证明图中结论正确。页面不执行材料中的 HTML 或脚本。

正文已有明确来源位置时显示可跳转编号；块级依据在该块就近标明，文末汇总固定来源。历史记录只有来源清单而没有位置时，不按顺序推测哪个论断对应哪条依据。章节装配关系与“归属对象”属于结构导航，不作为科学参考文献。新版记录写作要求见 [研究记录标准](RESEARCH_RECORDING.md)。

没有逐条 claim 的历史 Run 仍可查看，界面明确标记“待复核 / 未登记结论”。“未观察到风险”与“符合正式条件”分开显示；后者只用于逐条结论。来源不足时不会生成示例结论填补空白。

## 监测与候选的边界

监测限定工作区八类 Owner 的记录目录，沿用配置的文件数量/大小限制、支持格式与排除规则；公共 Owner 发现补入身份卡和记忆 HEAD。对象内 Run 与旧根 Run 按登记身份发现，规范 memory 提交目录不逐份扫描。Run 的输入/产物与来源引用只在上述记录范围内观察，`dist` 发布包、外部原件和缓存不会因被引用而进入周期哈希。证据图的间接核验同样受此限制，范围外显示“未核验当前指纹”，不能据此判为已变更或正式可用；显式正式核验入口仍使用原有完整校验。

HEAD 变化表示对象有新记忆提交，不表示每条 MEM 修订或文稿影响已审查。页面遇到单文件不可读或超限会显示诊断并保留其他可用记录；监测仍拒绝用不完整快照覆盖上一份基线。文件总数超限或证据图不完整也保留旧基线。单文件扫描中变化会报错，快照不保证多个文件的事务一致性。

第一轮只建立基线，不把历史 succeeded 记录误报成新完成。后续记录新增/变化/移出清单、Run 执行终态变化、复核变化、依赖风险变化。重复扫描同一状态不会反复追加同一变化事件。

“移出清单”可能是删除，也可能是修改了授权或扫描范围，不能自动判定磁盘删除。首次观察时间只是监测发现的时间，实际何时变化如果没有原记录则未知。风险消失只说明本轮条件变化，不会把复核状态改回 accepted。

维护候选有三类：检查更新、比较重复结论、比较相同字节材料。每项保存触发对象/版本与首次观察时间，不修改正文、不合并、不删除、不提升可信状态。重复结论按明确范围与规范化后的相同文本分组，仅用于人工比较；不是语义去重，也不说明证据独立。相同输入被不同 Run 或报告引用多次仍不能算多份验证。

候选由 AI 按实际证据处理；界面不提供一键复核或合并。检查更新候选保留待处理，其他条件不再出现时标为 condition-not-observed，历史仍保留。单独报告是否更正、业务结论是否复核需按正式流程记录。

## 持续任务

`evidence-monitor` 是可重复、可由调度器运行的单次入口。可以在宿主的定时任务中按选定频率调用；当前命令本身不会安装系统任务、启动常驻进程或改变系统设置。使用调度器时固定目标工作区与命令，正常轮询只更新监测记录；无变化无需重复汇报。失败应报告具体原因，不能自动放宽扫描范围或清除历史。

用于定时任务的任务说明可直接采用：

> 在指定研发工作区运行 automation/workspace.ps1 evidence-monitor。只报告新增材料变化、实验终态、依赖失效和新的维护候选。不要修改材料、执行实验、重建索引、合并记录或改变可信状态。重复被引用不算独立验证；失败时报告具体缺失，保留旧基线。

## 文件、备份与升级

- `automation/scripts/evidence_observer.py`：观察、差异与候选；`evidence_view.py`：只读服务和快照；`automation/ui/evidence.html`：页面。
- `context/monitor/state.json`：本机基线、观察事件和候选。它是独立观察历史，不是业务事实源；有锁且原子替换，不自动清空历史。
- `context/generated/evidence-view.html`：可重建快照。它与监测状态可能含内部内容，已从 Git 发布排除；完整获准离线包可包含观察历史。

旧业务记录不需要批量改写；新字段可选，没有 monitor 状态时首次运行自动建基线。更新框架时保留业务目录、对象内与历史 Run、规范记忆、来源配置及本机监测历史。监测的工作区内路径为相对路径；历史中文/空格目录测试只代表相应版本的合成检查，外部路径与调度器的绝对工作目录仍需在新环境重新核对。

升级统一使用独立新版源码和匹配依赖包：从新版目录执行 `setup.cmd --target "旧工作区路径" --register --open`，完成后继续使用旧目录。先关闭目标工作台、索引和实验进程；细节见 [部署手册](SETUP_WORKBENCH.md)。Git 拉取不是含备份、依赖与恢复的安装升级流程。升级后按需要检查（不改写旧业务对象）：

```powershell
.\automation\workspace.ps1 refresh-index
.\automation\workspace.ps1 validate
.\automation\workspace.ps1 evidence-monitor --dry-run
```

单独查看或轮询监测不要求重建向量库；框架/模型升级的索引处理以对应版本部署说明为准。完整模型和运行环境迁移另见 [Windows 迁移指南](WINDOWS_PORTABILITY.md)。不同版本的监测状态或损坏 JSON 会拒绝覆盖，需保留原文件后明确选择恢复或新基线；不会自动删除。
