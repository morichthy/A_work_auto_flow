# 按影响选择验证

分层记录独立性变更须由实际 AI 逐条只读本条背景/正文检查问题、条件、内容、结论和边界，保留改前缺口与改后固定版本；不以最少字数或标题匹配证明语义充分。确认状态展示覆盖逐 claim 未复核/已确认及旧内容绑定失效，保存成功不能变成已确认；对象记忆验证六类主筛选、章节归文稿、辅助记录与旧 event/map 可访问。真实记录浏览器阅读、软件回归与科学复核分别报告。

最近阅读改动应验证24小时边界、时区排序、查看不更新时间、历史保留与无全库慢路径，以及撤权/HEAD变化后旧展示失效；详情验证固定引用深链和metadata-only边界。公式渲染覆盖`$...$`/`$$...$$`及常见LaTeX定界，保护代码字面量，不能把裸公式当成已正确渲染。

note 正文与任务编排分离时，覆盖 Owner、综合、quick 和 legacy 交接，确认正文保留材料限制而非 reader 决定，缺口状态仍可见。分类型证据页覆盖 L0–L4、Run、完整 document、显式正文/块级引用及无位置旧引用；图片需在真实浏览器实际解码，并测试撤权、固定指纹变化和越界拒绝。移除重复阅读入口后，验证首页模式控制和默认保存、旧链接转向及摘要到详情导航。无关索引故障不得污染健康详情，真实损坏目标仍须报告。

本页规定测试强度，不规定固定开发流程。根据功能重要性、改动大小、影响范围及失败后果选择有用的检查；选择理由写入本次计划/摘要即可。复杂执行可用现有测试器保存冻结选择与独立回执，命令和 AI 场景见 [TESTING_REFERENCE](TESTING_REFERENCE.md)。

## 选择范围

| 改动 | 验证目标 | 通常采用 |
|---|---|---|
| 纯文档、计划、低风险规则调整 | 现行含义、链接、入口和历史保护 | 定向文档核对；不强制创建新 Run、跑 quick/full 或生成 AI 验收全套记录 |
| 局部低风险功能或明确缺陷 | 改后行为可用、关键失败边界不回退 | 轻量核心：受影响行为的现有测试，必要时补真实故障用例；不为可逆改动编写只匹配实现文字的测试 |
| 重要功能、跨模块或状态/契约变化 | 主要使用链路、调用方、失败/兼容边界一致 | 详细关键功能回归，覆盖架构影响表的相关路径；可用 quick 加影响能力，但不是默认要求全库回归 |
| 全局重构、广泛影响的收口或发布 | 受影响系统整体可交付 | full 及相关集成/交付检查，明确依赖缺失和未执行项 |
| AI 调用、语义内容、研究续接方式变化 | AI 实际能完成本次任务 | 在软件检查之外选择相关 A01–A09；不自动全选，普通界面/文案改动不默认触发 |

通过必要检查后，只有新改动、失败或未解决风险才扩大/重复验证。复用已有证据先核对版本、输入和适用范围。新增能力/真实故障补入可复用测试目录；已选测试不能为追求通过而降低标准。

当前 `testing prepare --tier quick` 的选择器仍包含固定跨栈门槛和影响能力集合，**不等于上表的最小轻量集合**。轻量检查可直接运行相关既有测试并记录结果；本规范不虚构尚未实现的“轻量 tier”。需要机器冻结、全量核对或完整执行时再用 quick/full 工具，详见执行参考。

## 测试点生成与持续维护

从本次目标和架构影响路径识别用户可观察行为、状态转换、关键失败/拒绝及兼容边界，再选择已有测试；确有缺口时补行为用例。真实故障尽可能固化原触发条件与错误结果，修复后验证正确行为；不要只匹配实现文本或为增加数量重复测试。测试点由开发者/AI 设计，静态发现只能发现已有用例，不能证明需求没有遗漏。

测试定义和基线成员唯一维护在 `automation/testing/catalog.json`；具体断言在该项 `path` 指向的测试中，执行证据留在任务摘要/Run。新增、改名、移动或删除用例时同步登记并盘点；功能、契约、来源边界变化及真实故障出现时，检查相关测试的断言和负例是否仍有效。修改相关能力时同时复审它的基线，发布前通看基线覆盖缺口；不要求每次小改动复审全库。

## 基线防线的准入、复审与退出

基线是 `quick=true` 的固定跨栈防线，用于保护重要且需要长期保持的行为，不是全部功能测试，也不是每次开发必须全跑的集合。新增登记默认只进入 full；选择 quick 时，工具合并固定基线、受影响能力和显式追加项。轻量任务仍按上表选相关检查。

- **准入**：用例保护数据/权限/固定版本/恢复等重要边界，或核心用户链路、跨层契约、后果严重的真实回归；具有明确断言、可重复输入和可解释成本。先找现有覆盖，避免重复堆入；较慢但不可替代的交付防线可以保留，并说明原因。新增重要能力必须作出“加入基线 / 已有覆盖 / 仅按影响执行及理由”的明确判断，不因已登记就视为已覆盖。
- **逐项依据**：基线项的 `baseline` 对象维护 `risk`（失效后果）、`reason`（保留理由）、`review_triggers`（相关行为/边界变化）、`reviewed_at`、`reviewed_by` 和 `review_basis`。复审记录是设计判断，不代替执行结果；未知的历史选入日期或原始理由不补造。
- **复审**：触发相关变化时检查是否仍能捕获目标故障、断言是否变弱、是否与其他项重复、依赖/成本是否适合固定执行。记录保留、加强、替换或退出及原因；同时检查新能力有没有基线缺口。没有触发无需机械改日期。
- **替换/退出**：只有原行为已正式取消、风险已消失，或已有明确替代测试覆盖相同必要边界时才能退出。替代须记录具体测试 ID、覆盖对照和实际验证依据；保留原项时把 `quick` 改为 false 并保留其依据，删除用例时在清单历史保存旧项。慢、环境缺失、暂时失败或追求通过率均不是退出依据；暂未运行如实记录 incomplete/未执行。
- **变更留痕**：同次变更更新清单 revision，在 history 记录操作者、时间、原因、受影响 ID、前后依据及可用验证引用，并保留旧清单/差异。已冻结选择不回写；需要执行新范围时生成新选择版本。新增或替换的防线需实际验证，纯补充依据可定向核对清单与选择行为。

这些字段是开发维护约定；当前 `audit` 不强制校验 `baseline` 字段或判断风险覆盖，也没有自动晋升/退出命令。修改清单后人工/AI 核对依据完整性，再用 `testing audit` 检查登记与定位。当前基线的依据补录不等于对新材料查询等所有能力完成了全面覆盖审查。

## 不能省略的风险检查

Owner 文稿阅读检查：跨路线相同正文块去重、候选仅正文和 owner_id、选中后不重复交付同 Owner 候选；每次读取一个 Owner 的完整文稿，缺文稿/只有精简报告须显式报告。图片及 L0/Run 先保留固定引用，显式展开须重验权限与版本；不得将未展开原件写成已读依据。检查 note 的问题/条件、关键细节和固定出处、整条交接及超限提示，撤权/陈旧来源、保存进度和旧 RS 兼容。AI 输出与内部诊断分别计量，Owner 数与最终 note 估算 token 由同一设置契约提供；实际宿主 token 不由软件测试推定。note保存检查正文引用漏登/未知ID、中文标点与来源ID边界、无关来源不强制加入、拒绝不写note/历史修订/副本（只允许既有消耗审计变化）；现存note交接不追加回溯语义复检。reader派工与实际AI场景验证提取/同任务自查，和程序可判定的引用检查分别记结果。

三模式阅读还须覆盖：默认 strategy 与 association 配置严格校验、reading-configure 的CAS/幂等和不启动搜索；standard/associative 的Owner全文路径；associative 的实际查询文本、开关与轮次上限；quick 只对实际交付片段 assessment，拒绝未交付片段和全文读取，note 标明片段覆盖。综合note须固定Owner note底稿与实际来源，底稿或来源改变后不交接旧综合稿并公开缺口。前端覆盖设置默认模式、会话保存/冲突草稿及quick非全文提示；浏览器、真实AI和人工验收另记，不能由组件或单元测试代替。

工作台监测与视图状态变更核对：Run 引用的发布 ZIP/外部来源不得进入 Owner 记录周期哈希（包括间接证据核验路径）；文件异常可展示其他证据但不能覆盖完整基线。组件及浏览器覆盖首次读取、切页保留结果/筛选/草稿、对象记忆显式生成、默认标签顺序，以及对象切换后旧请求晚到的隔离。相关源扫描变化仍执行真实 setup 扩展旧工作区测试。

子Agent阅读分别验证路由声明与真实宿主派工：auto/off/无宿主回退、只读revision、同RS累计预算、撤权/陈旧来源、notes-only内容和整条省略上限、检索覆盖缺口与ask_user传递。用独立低成本Agent实际检索、全文阅读、写note，主侧只回读handoff；字符减少、语义自查与软件通过分别记录，不推断总费用或正确率收益。

工作区设置验证缺文件默认、严格字段/预算上限、并发CAS、锁与失败保旧、外部修改缓存失效；公共HTTP/CLI与新模板消费同一设置，旧RS固定预算不变。组件/浏览器检查冲突保留草稿、显式保存和单位换算；真实setup将用户设置加入共享保护fixture。缓存微测仅衡量配置读取开销，不能证明端到端召回提速。

子Agent能力偏好扩展另查：旧文件缺字段只在内存补默认、严格完整写入防丢偏好、非空文本和长度限制、自定义要求传到policy/委派包、off始终优先；前端保存/重载/恢复默认/冲突保留文本，真实setup保护自定义能力要求。模型文本传递的软件通过不代表宿主存在该模型或模型一定满足实际任务质量。

正文重排新增基线：固定候选覆盖与oracle上限、当前RRF的Recall@6/nDCG@6；对照真实CE短输入、必要上下文及显式条件。分开开发/留出，不用标签制造条件特征；无答案空池不能证明拒答。软件防线覆盖输入过长/缺上下文、条件unknown与矛盾、实际批次费用、模型变化分页、撤权与旧RS兼容。新模型组件另外走完整离线安装升级再打包恢复，真实模型测试和假评分器控制测试分别记录。

Owner压缩发现索引的固定功能基线覆盖：发现表/向量collection与全文索引隔离，L4/L3/L2紧凑内容和L1检索说明的确定性投影，Owner HEAD/来源变化后的stale拒绝，权限/排除不被投影绕过，路线内Owner折叠和跨路线provenance，互补筛选包上限，CE单窗口超长不拖累整批，以及未经用户明确选择不得执行全文补偿。旧Owner修复流程还需固定低等级模型任务范围、MEM CAS提交、回读后逐Owner重建、不改原件/review和失败可续接；本次既有长期 Owner 审核没有发现内容结构缺口，因此只验证了缺口识别、派生重建和不写规范内容，没有制造语义修订冒充实际修复。测试条数上限只保护接口，不在本阶段评价候选数量收益；Recall、延迟、CE成本、上下文占用和错误联想率暂不测。完整矩阵与实际结果见[实施计划](../projects/architecture-evolution/plans/owner-discovery-retrieval-20260918.md)。

- 校验、目录扫描、缓存边界、工具登记、框架清单、安装或恢复逻辑变化：真实 `setup.cmd` 扩展旧工作区场景，覆盖预览、升级、重复升级、恢复、完整受保护文件/目录及真实损坏拒绝。见 [UPGRADE_TESTING](UPGRADE_TESTING.md)。
- 前端变化：相关组件、实际浏览器、类型检查、构建和资源指纹；使用端不依赖 Node。详细命令见 [WORKBENCH_DEVELOPMENT](WORKBENCH_DEVELOPMENT.md)。
- 依赖/模型变化：真实离线安装、升级、接收端再次打包与恢复，不能用 core 安装替代。未变化的依赖不必重复打包。
- 检索、表示或知识语义变化：范围/排除、固定引用、正式准入、L0 边界、预算及相关性；涉及策略收益时比较准确度、召回、错误关联、延迟和上下文成本。
- 每次代码修改核对 Windows x64 与旧工作数据升级边界。第二台物理机及真实业务验收独立；当前万条规模测试保持暂缓。

## 结果怎样记录

证据引用还要验证作者的编号清单与 sources/payload 合并顺序不同的场景，不能让正文[1]和自动参考文献[1]指向不同来源；已有局部编号保留，链接按实际固定身份/版本生成，未知或歧义不猜。

阅读上下文界面检查：有笔记会话默认显示、刷新保留当前选择、Owner 与 RS 标签分离、空页/分页/不可读提示和跨对象晚到请求隔离；首页与阅读页共享选择，证据入口只关联实际笔记固定来源，材料主题深链接进入对应 Owner/记录。后端验证更广当前授权域可查看限定会话但不扩大查询范围、不足授权仍拒绝，Markdown 副本失败不回滚已提交状态，旧会话兼容。可读副本不参与普通检索/通用上下文注入，不进入源码分发；真实 setup 扩展旧工作区按完整保护清单检查副本和 RS。

软件执行、实际 AI 自查、人工反馈与科学复核分别保存，不能累加成一个通过率。失败、跳过、未执行及待审如实保留；`audit/coverage` 是盘点，代码阅读是静态核对，都不等于行为测试通过。

实际 AI 需真实读取、生成请求、走公开入口并固定回读，然后自行评估；程序不能代填。A02 必须是真正独立上下文，人工没有给结果仍是待审。人工页只包含本次新增及重要受影响功能。

小任务在计划/摘要记录目标、影响、检查及结果；有独立输入/输出或长期复用价值的验证用 Run 固定源码、输入、命令、回执与限制。已有失败和旧版本保留。结构变更执行 `refresh-index`、`validate`；本页不要求每次都创建全套分层成果。
