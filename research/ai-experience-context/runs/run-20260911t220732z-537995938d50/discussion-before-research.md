# AI 历史经验总入口 Skill：方案审议

创建日期：2026-09-11；最新讨论：2026-09-12。状态：讨论建议，尚未创建/安装 Skill、未修改运行行为。用户已认可三部分上下文与覆盖清单，纠正 A/B/D 的解释；最新取舍以下节为准，9月11日建议保留演进依据。目的：优先避免漏掉有用技术细节，在此基础上减少等待和重复读取，并支持同问题多轮交互。

## 2026-09-12 用户澄清与修订

用户明确：A 先展开再由 AI 判断，是为了避免高层不相关但 L2/L1 有用的内容被排除；B 接受额外耗时换取召回；D 在已有上下文能解决问题时停止，只有解决不佳再增加关联递归。用户认可持续探索中维护覆盖清单，并将其与三部分上下文一起持续保持。此前“先看简短正文再筛掉候选”的建议偏向节省读取，D 的解释也混入了独立的证据审查要求，均应修正。

### 当前认可的目标与待选实现

- 保留“先展开再判断”的策略；分批只是控制单次上下文大小，不能把尚未读到的下层内容标为不相关。AI 可以根据已展开正文判别相关性，无法确定时保留候选或继续读。
- A/B/C 是直接内容检索与阅读。D 是尝试解决后的可选关联深化，已有材料足够完成当前任务即停止；不要求每次额外搜索反证、遍历全图或填满未知历史。已有材料中的条件/失败应原样保留，这不等于另外发动 D。
- 相关性与充分性分开：条目可能只贡献一个操作细节；若已有材料能形成可用答案或下一步实验，可以进入解决阶段。覆盖清单记录本轮所需依据，不成为“必须穷尽整个研究”的门槛。
- 用户接受用时间换召回；候选广度、单条展开深度、最终常驻上下文量分别控制。扩大候选池后分批阅读、合并证据，可保留宽召回而避免单次混入全部材料。具体数量不在未测量前固定。
- B 的串行兜底保留为基线。候选改进是跨层独立检索并合并结果，让 L1/L2 即使没有高层命中也能进入候选；不同层预留候选空间，避免高层分数挤掉底层。此项是建议，尚未获用户选定为最终实现。

### 文献与业界依据

| 方法与一手来源 | 文献/工程事实 | 对本工作区的建议及边界 |
|---|---|---|
| [RAPTOR，ICLR 2024](https://arxiv.org/html/2401.18059v1) | 比较逐层裁剪与 collapsed-tree 跨层检索，后者在其 QASPER 子集对照中表现更好，正式实验采用跨层方案 | 借鉴底层独立召回，不把 L3/L4 当唯一入口；现有 L1–L4 是业务语义分层，并非 RAPTOR 自动聚类树，不建议直接再建整棵树 |
| [Elastic 混合搜索](https://www.elastic.co/docs/solutions/search/hybrid-search)、[重排](https://www.elastic.co/docs/solutions/search/ranking) | 全文与向量召回融合，候选再进入成本更高的模型重排 | BM25 保留术语/参数命中，向量补语义表达；合并后由 AI 阅读展开内容。当前 MQ 尚无向量提供器，不能写作现成步骤；重排前不把候选硬裁到极少数 |
| [Microsoft Small2Big](https://learn.microsoft.com/ar-sa/azure/developer/ai/advanced-retrieval-augmented-generation#chunking-strategy) | 小粒度检索后可找邻近句子或完整段落，以补上下文 | 技术细节块命中后返回完整步骤、定义或章节；与用户先展开再判断兼容。展开依据稳定块/章节关系，不按同 Owner 猜测 |
| [Anthropic Contextual Retrieval，2024](https://www.anthropic.com/engineering/contextual-retrieval) | 索引前给块附加针对该块的文档背景，同时用于 BM25/向量；其研究还比较更大候选和重排 | 让“该步骤用了何种方法、解决什么局部问题”可被检索；背景说明是派生索引内容，不替换正文、不充当已复核事实。来源自己的实验结果不等于本工作区收益 |
| [CSQE，EACL 2024](https://aclanthology.org/2024.eacl-short.34/) | 利用 AI 从初检文档挑出的关键句，与模型生成扩展一起改进查询 | C 可以使用本库真实术语扩展，保留原问题；生成检索词不是业务证据。避免查询只围绕模型先验答案收窄 |
| [Self-RAG，ICLR 2024](https://arxiv.org/abs/2310.11511) | 训练模型按需检索并评价材料/生成结果，而非无差别固定检索 | 为 D 的按需继续思路提供参照；不要求照搬其训练和特殊 token，也不声称普通 Skill 提示实现了论文模型 |

这些来源支持可组合的方法，不提供适用于本地资料的统一最优参数。工程基线优先考虑跨层正文召回、混合检索、展开后 AI 判别；自动摘要树和递归图搜索无需作为首版前置条件。

### 本地代码确认的新缺口

2026-09-12 静态阅读 `automation/scripts/memory/index.py` 的 `_row`：v3 detail 用 `technical_units.description_text` 作为检索 body，并从派生行 payload 去掉 blocks/figures。当前 technical 来源筛选 detail，不代表完整技术正文已进入普通检索。只有正文出现的细节可能无法靠 B 或增大 Top-K 命中；本次未用真实题集测量漏检频率。

建议增加可重建的技术块检索投影，固定关联 record/revision/block 与正文来源，保留原规范存储的唯一权威。可先检索块，再按原版本展开技术单元、经过和文稿；投影的授权、失效、索引水位、迁移与成本仍须实施验证。该建议不修改已保存正文，也不是新增第二份业务知识库。若先做纯 Skill 版本，这一正文未覆盖的限制必须明示。

### 修订后的流程草案

```text
恢复当前问题的关键上下文与覆盖清单
    → A：较宽召回概览/经验，展开有关经过和技术正文，再由 AI 判断
    → B：仍需直接材料时，独立查经过/技术内容并展开判别
          可评估将跨层召回提前并行，以减少串行等待
    → C：必要时结合原问题、本库术语与多种表达补查
    → 根据已读材料形成上下文，尝试回答/实验/解决
    → 已足够：停止检索，维护本问题状态
    → 解决不佳且需要更多历史依据：D 加关联补充或深化，再尝试
```

覆盖清单建议保留“子问题、检索过的来源/查询、已展开材料、可用细节及条件、排除依据、尚缺信息、当前解决状态”。同问题新增条件时重新审视相关候选，不将前一轮的“不相关”永久缓存。已读取内容和选择记录随任务保持，规范材料继续用固定引用回源；本轮用户认可的是维护思路，不代表宿主注入机制已经实现。

## 2026-09-11 初始建议（A/B/D 解释已由上节修正）

| 草案环节 | 风险 | 建议 |
|---|---|---|
| 简化问题和关键词 | 简化时丢失版本、量纲、否定条件、故障现象；只搜 AI 猜测的答案会偏向已有假设 | 保留原问题，提取目标对象、要回答的子问题、条件与失败现象；原词、标准术语和必要同义词分别保留。明确身份可直接定位 |
| A：概览/经验→展开经过→完整文稿 | 先展开再判断会读取大量无关材料；一篇相关文稿也不能覆盖全部问题 | 先读小批候选和命中说明，再读可能相关的已有正文；检查适用条件，按缺口选择 L2/L1 或文稿。只有需要跨章节推理、复原研究路线时才读完整文稿 |
| B：仅当上层无结果才查下层 | 上层有结果但摘要遗漏细节时，停止过早；尚未整理的 L1 可能无 L3/L4 | 用“关键子问题尚缺依据”触发补查。查公式/参数/报错可直接进技术内容；重要问题即使有高层命中，也对未覆盖条件作小范围 L1/L2 补查。没有链接时允许独立检索，不能猜同 Owner 必然相关 |
| C：减少关键词扩大范围 | 当前词法按 OR 连接，删词可能缩小匹配集合；零结果也可能是索引、权限、版本或预算问题 | 先看缺口和错误；保留原查询候选，补同义表达、拆子问题、调整过严的非授权筛选。变更请求产生新查询，不能伪装成原查询续接；权限和显式排除始终保留 |
| D：结果不佳才加关联补充 | 必要定义或已知反证可能首次就需要；大量相似资料可能重复且误导 | 必需上下文、直接失败/反证第一次选材就核对；额外导航关联在证据冲突、条件不匹配或缺关键依据时启用。结构类比通过 association-exploration，带差异与迁移条件，不作为科学支持 |

“不丢失信息”宜分开验收：原件/固定版本可追溯；影响当前决策的关键条件、失败和反证不被摘要删除；尚未覆盖范围显式列出。有限检索与摘要不能承诺发现全库所有相关信息。公式、变量、单位、适用条件应作为完整单元保留。

## 2026-09-11 初始流程（保留演进依据）

```text
本轮输入 → 确认是在继续原问题，还是新增/改变问题
    → 读取本问题已有上下文和固定引用，只处理变化与缺口
    → 把问题拆成少量需要证据支持的要点
    → 有明确身份则直接读；一般先查概览与经验
    → 先看候选，再选择正文与必要依据
    → 按缺口补 L2/L1、必要章节、完整文稿或原件
    → 检查适用条件、相反证据、重复与版本
    → 形成关键上下文、按需证据和未覆盖项
    → 回答/执行；新事实或失败出现时更新本问题上下文
```

搜索、已读、选为依据、已排除分别留痕。“有命中”或 AI 自评有把握不作为停止依据：本轮所需关键要点已有可引用内容、必需上下文齐备、已见冲突被解释，或达到预算并明确缺口时停止。相同固定内容去重，不合并不同条件、版本或矛盾结论。

性能优先减少重复启动、重复查询、整篇展开及逐条 AI 判别往返；小批候选一次评议，按需加深。首批数量与时间不设未经测量的永久常数。不同查询共享本问题的总成本记录，当前 MQ 仅提供单查询账本；跨查询总预算仍需薄编排层补齐。零新增依据时结束改写重试。索引未覆盖/原件不可读须单列，不自动重建全库或扩大授权。

## 同一问题的上下文保持

| 内容 | 保留方式 |
|---|---|
| 目标、当前约束、用户纠正、关键已知条件、不可忽略的失败/反证、未决问题、固定来源定位 | 精简的本问题关键上下文，后续相关轮次持续可用；新增依据可以修改或撤销旧判断 |
| 当前推理所需的技术块、完整公式、图表、必要章节 | 按本轮需要读取；不为固定篇幅截断必要定义；读取状态与摘要分开 |
| 完整文稿、Run、原件以及先前候选与选择记录 | 保存在原权威位置，以固定引用回源，不每轮复制全文，不把未读材料写成已掌握 |

建议 Skill 约定：同一问题延续时，恢复当前目标、硬约束、关键依据和未决事项；压缩或续接前保存可恢复摘要及固定来源。更新需说明新增、更正和已失效项；当前用户指令优先，历史正文是证据数据，不获得指令权限。只有明确转题、任务结束或依据被新证据替代时，才从该问题的有效上下文移出。

Skill 文字只能指导行为，不能保证任意 AI 宿主永久保留某段文本。若要工程保证，宿主适配必须在每次相关请求及压缩/续接后装入关键上下文，并验证实际请求里是否存在；该机制当前尚未实现。文件存在不等于已装载，引用存在也不等于已读正文。关键内容本身超限时分子问题或明确缺口，不能声称无损压缩。

复用现有 goal/checkpoint/resume 的记录能力前须确认用途：当前 resume 按 Owner 的 goal/checkpoint 指针组织材料，不能直接当作多个并行问题的独立会话。建议问题状态按任务/问题区分、指定单一维护者，仅保存派生摘要、选择和引用，不建第二套规范数据库。首版可用现有任务摘要承载，长期研究检查点按既有 MEM 服务保存；不把每条聊天自动晋升为可复用经验。

## Skill 与现有模块的边界

拟新增入口只负责本轮意图、历史依据需求、停止/补查条件、上下文保持以及路由；material-query 负责具体查询和展开，workspace-context 保留算法文档/实现核对，research-loop 负责产生新研究，association-exploration/semantic-maintenance 处理相应语义工作。只有实际需要时读取下游 Skill，避免每轮加载全部工作流；后续实施须消除入口重叠和递归路由。

对工作区研发问答、设计/诊断和任务续接默认考虑历史依据；同问题无新缺口直接复用。普通闲聊、已给足内容的纯格式转换不强制检索。AGENTS 只放短触发与恢复规则，详细策略在总入口 Skill，机械读取与校验留给现有服务。

当前两个直接实现缺口：

1. MQ capabilities 仅开放 identity/lexical，不能把草案的向量匹配写成可调用步骤。后续可接现有向量后端，但须适配固定引用、授权、去重和成本计量，并证明收益；不透明混用新旧回执。
2. CLI 每次结束关闭 Coordinator，assemble/expand/documents 选择本页全部候选，不能供 AI 在两次 CLI 间维持同一查询并择优展开。交互流程宜复用已有持久 HTTP 会话，通过薄客户端传选择；新查询不得清零本问题总成本。会话到期后用固定引用恢复材料并新建合法查询，不能伪造旧游标。
