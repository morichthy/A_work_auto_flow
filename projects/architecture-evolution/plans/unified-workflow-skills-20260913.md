# 统一工作入口、分层经验与 Skill 精简计划

2026-09-13。归属 PRJ-ARCHITECTURE-EVOLUTION；状态：已实施并完成本轮整合审查。原计划正文保留作为选择依据；实际结果、逐项Skill/文档审查及验证见[实施Run](../runs/run-20260912t211413z-6272d2e02162/RESULTS.md)。A–D已落实；598项后端全量已执行，本次相关失败修正后定向复验通过，既有B01冻结基线失败单列保留。38项组件、16项不同普通浏览器场景、18项不同升级检查均有通过回执；实际AI合成任务完成，业务质量/人工/第二物理机不追认。用户方向：各类工作采用同一套可追溯记录逻辑，各类资料都可成为可复用经验；主Skill精简，给AI留出方法选择空间。

## 1. 目标与取舍

面向 AI 的主入口暂名 **work-loop（工作与记录）**。它只规定归属、记录、公共工具调用和用户交互；问题拆解、先读什么、采用什么方法、何时已有可行下一步，由 AI 结合实际任务判断。

统一的是工作协议和信息表达，不把全部对象搬到 research，也不把所有内容都标成 L3 experience。Research、Project、核心算法、工具、数据、知识、报告和 Run 继续作为有稳定身份的 Owner。来源材料、他人主张、AI 理解与本机实际验证继续区分。

主要收益目标：少选工作模式、少读重复规则、少填重复记录；核心算法用途、工具做法、使用失败、报告依据等均能按内容被找到。不能以 Skill 文件变少代替实际减负，也不以软件可运行代替检索质量提高。

## 2. 共同记录语义

L0–L4 表达内容职责，不是可信等级或必须逐级完成的流程。按有用内容产生记录；允许 L0+L4、L0+L1+L3 等组合，不为省略层级生成空白条目或说明文件。

| 层 | 统一用途 | 来自外部文档时 | 来自实际工作时 |
|---|---|---|---|
| L0 | 原始依据及版本定位 | 原文、章节/页码、来源版本、原件引用；授权范围内保留原文或受控引用 | 代码版本、输入、参数、输出、日志、执行回执 |
| L1 | 可完整理解和复用的技术内容 | 方法、公式、操作步骤、接口与条件；标明摘编/分析及未实际执行 | 开发方案、脚本方法、实验、推导或分析及限制 |
| L2 | 有依据的经过、选择与转折 | 文档明确记载的开发/实验经过，注明是来源叙述；或我们实际整理、取舍的经过 | 为什么这样做、尝试结果、失败、修正及下一步 |
| L3 | 可迁移的认识和使用建议 | 文档主张、适用条件、用途、注意事项或 AI 有依据的提炼；不假称亲自验证 | 经本次工作支持的观察、结论、假设或建议，保留边界 |
| L4 | 对象的简明介绍与导航 | 是什么、解决什么、何时使用、输入输出、重要关联与限制 | 当前能力/结果、阶段、待解决问题与相关入口 |

纯粹的“第一步、第二步”操作说明通常是 L1 方法，不因此证明曾发生研究经过；有实际或文献记载的演进、选择、结果才进入 L2。用户希望步骤可检索的目标通过 L1 正文实现，无须虚构 L2。概览、用途、关联也不必重复生成一份 L3：只有形成独立可复用认识时再提炼。

来源叙述、本次观察、AI 推断首先复用固定 sources、现有知识分类、正文和复核字段明确表达；先测试能否稳定区分，确有机器筛选缺口才增加小范围兼容字段。不能直接向现行 schema 填未支持的枚举。资料中的数字不得改写为本次 Run 结果；文档认可状态不自动传递给提炼记录。

## 3. 工作场景与归属

| 场景 | 默认归属及保存内容 | 不要求做的事情 |
|---|---|---|
| 整理公司核心算法介绍 | 已有 MOD；登记原文，建立用途/适用域概览，按需要抽取 L1 方法与 L3 认识；实际比较或整理转折才记 L2 | 不为介绍文档造实验、造过程；不把普通工具提升为核心算法 |
| 撰写可复用日常脚本 | TOOL；源码留 tools/scripts 或 tools/packages，开发方法/关键取舍归工具 memory，验证归 Run | 不把研究笔记放进源码目录；不按每次编辑建研究 |
| 用工具处理业务数据 | 业务问题所属 Research/Project/Data 的 Run；登记所用 TOOL 和代码版本。独立工具测试/基准才优先归 TOOL 的 Run | 不把每次工具使用都搬入工具 Owner；不把同一运行复制给多个 Owner |
| 从使用中发现工具经验 | 在原 Run 保留事实，将通用用法/限制以固定引用归 TOOL；业务特有结论留业务 Owner | 不把单次数据表现推广为工具普遍能力 |
| 项目开发、修复与验证 | 已有 Project，按实际内容保留方法、选择、测试依据和阶段概览 | 不额外包一层 Research，不为排期/拼写等补造技术经验 |
| 持续专题探索 | 已有 Research；独立执行归 Run，重要方法/经过/认识和概览按需保存 | 不要求每次聊天更新全部层与双文稿 |
| 生成或阅读报告 | Report；原报告/产物登记、用途/受众/范围概览，技术依据固定引用已有记录；需要时提取独立方法和认识 | 不复制报告引用的全部实验，不把报告结论当作新验证 |
| 整理知识与外来资料 | 已有或采用后的 Knowledge Owner；保留来源，按内容生成概览、方法、认识与关联 | 不要求先放入 Research 才可检索，不把全部知识都标为已验证经验 |
| 数据诊断或一次性分析 | 已有数据/业务 Owner，或无明确归属时独立 Run；输入、方法、结果、限制 | 不为短分析新建空项目 |
| 极小且无独立复用价值的操作 | 可不新增记录；自然纳入已有任务的结果即可 | 不为每次查询、每个工具调用建知识条目 |

AI 优先沿用当前明确 Owner，再按工作目的选择，必要时创建；用户指定优先。归属并不决定可信状态，也不是读取授权。跨对象引用复用，一个事实保留一个权威来源。

“小工作”按后果和信息价值判断，不单看耗时：短操作若改了重要配置、产生关键反例或影响可复现性仍需记录。一般开始前只确定归属和必要输入，不强迫立即创建全部档案；独立执行时保存事实，形成有价值理解/选择时增量保存，交接时更新当前状态。

## 4. 存储和运行中的可见记录

优先沿用现有 Owner 适配器返回的 native_ref、memory_home，不因统一理念迁移业务文件。

```text
tools/
├── registry.json                 工具身份与源码入口
├── scripts/ 或 packages/         源码和源码测试
├── memory/TOOL-ID/               工具方法、用途、开发经过与使用经验
└── runtime/TOOL-ID/runs/…/       工具自身验证/分析及执行材料
```

Research/Project/MOD 继续使用各自 memory/、runs/。当前 Knowledge/Report/Data 为身份绑定文件的旁置 memory 路径；以 list-owners 返回值为准，不凭文件夹名称移动。这些路径已存在于当前适配，不宣称本计划新增。

运行中三类状态各有职责：Run 留实际执行事实；RS 留当前问题的已读理解、必要细节和阅读尝试；Owner 的记录/检查点留长期成果和交接位置。避免三个地方各维护一份不同的“当前计划”。总目标/阶段下一步以 Owner 或独立 Run 的交接记录为准，RS 的 next_step 明确为阅读子任务状态。

计划接通稳定 Owner/检查点到相关 RS 的显式引用和便捷查看入口。先检查现有字段是否可承载；不向只能引用 MEM 的字段硬塞 RS。需要时最小扩展接口，明确删除/归档/撤权与历史恢复语义。不得新建平行 Task/Experience 数据库。

交付时应能从对象入口找到运行中的阅读清单、已读/未读状态、源链接、必要细节和下一步，无须用户寻找 UUID 或手写 JSON。优先增加公开“列出/查看”与易读输出，工作台入口按已有页面小范围接入。JSON 为权威状态，Markdown 为标明版本的导出视图；不得把静态导出描述成实时更新。读取来源撤权后不得从旧导出自动绕过权限。

## 5. 主 Skill 草案

以下是待实施的正文骨架，不是当前已安装能力。目标正文约一页（建议约600–1000中文字，不含独立接口参考）；超过时先删除重复规则或外移参数说明，不把长规则改成一串必读链接。

> **work-loop：工作与记录**
>
> 在本工作区开展有实际产物、结论或复用价值的工作时使用。用户目标与归属指定优先；方法、拆解、读取和验证强度由 AI 按任务判断。
>
> 1. 沿用或选择合适的 Owner；已有工作先恢复必要目标、依据和下一步。极小且无复用价值的操作可不新增记录，不为分类另造项目。
> 2. 需要本地依据时使用 material-query，完整阅读保留材料并维护理解、必要细节与出处；已有依据足够就推进，无须每次重新搜索。
> 3. 独立执行建立 Run，适用的脚本用 run-execute，其他工具/已有产物用 run-register；保留真实输入、版本、输出和失败。无执行的分析可以直接记录。
> 4. 有用内容按职责保存：原始依据L0、完整方法/分析L1、有依据的经过L2、可复用认识L3、介绍/阶段概览L4。按需组合，不凑层、不复制来源，不把文档主张或AI推断当作本次验证。
> 5. 用公共 memory 接口提交并回读，确认保存/索引状态。阶段结束或交接时留下当前结果、依据、未解决处和可执行下一步；文稿按实际阅读/交付需要编排，不要求每个任务双文稿。
> 6. 自主推进已授权工作；方向、资源或权限需要用户决定时再询问，说明具体缺口与选择。按当前失败和证据决定补查，不以固定次数替代判断。反馈时给出结果和可打开的记录链接。
>
> 命令参数从对应 --help、模板或单一接口参考按需读取；专项开发/数据约束按受影响内容查阅。来源版本、权限和验证状态不可省略。

主 Skill 不规定固定的假设矩阵、先外网后本地、固定研究轮数或强制报告结构。固定引用、授权、版本冲突、实际执行记录等能由程序检查的要求交给程序。接口参考按“读/找、执行、保存、交接”四组提供实际命令和最小请求；复杂 JSON/schema 不嵌入正文。

## 6. Skill 整合与发现入口

| 当前入口 | 计划处置 | 保留的职责/去向 |
|---|---|---|
| research-loop | 合并重写为 work-loop；旧名称保留短兼容入口，迁移验证后退出默认发现 | 统一记录和交接；研究专门方法变为可选参考 |
| workspace-context | 通用部分并入 work-loop/material-query，退出默认模式选择 | 核心算法文档优先、文档—实现核对等进入专项参考；旧CTX能力保留兼容，历史ID不改 |
| material-query | 独立保留并精简 | 查找、完整读取、阅读记录；参数/旧查询入口外移参考。第二次扩查强制人工门槛调整为按风险/代价和用户偏好判断，程序与文档同步 |
| context-maintenance | 普通归属/登记/保存并入统一入口，专门批量接入与整理保留按需方法 | 不再作为日常记录的第二主入口 |
| development-checks | 保留开发专项能力，退出普遍研究的必读负担 | 按影响选择验证、Windows升级保护与现行文档维护；评估六份文档每次全读及逐项Skill全审的触发条件 |
| association-exploration | 独立按需保留 | 需要专门结构迁移分析时使用，日常阅读笔记的间接启发不强制调用 |
| evidence-inspection | 独立按需保留 | 查询复核、证据和下游影响；普通查看已有结果不反复套流程 |
| semantic-maintenance | 独立按需保留 | 实际下游语义修订、预检/提交；日常写笔记不触发整套维护 |

run-execute/run-register 是工具，不建立同名主 Skill。文档、表格、PDF等成品 Skill 继续负责格式质量，统一入口负责它们的归属与记录。

根 AGENTS/START_HERE 中给出一条默认入口规则和明确的小任务例外，更新 .agents 发现入口、安装登记、README 导航及旧名称跳转。Skill 默认调用仍由 AI 执行；没有模型执行的后台进程不能宣称自动写经验。验证必须观察真实 AI 的工具调用与产物，不能只改 description。

## 7. 检索统一必须真正接通

不能只在所有 Owner 下写出 L0–L4 文件。需要逐类验证：对象发现 → 记录提交 → 当前索引 → 各层召回 → 固定正文展开 → 来源与版本回查。

- 检索以内容与适用条件为主，Owner 是可选范围和归属，不把 tools/reports/knowledge 自动排除在“经验”之外。
- L4 包含用途、目的、输入输出、适用边界和有依据的关系；L1 保留具体方法和步骤；L3 保留实际可复用认识。只在标题出现对象名不能代替正文发现。
- 外来材料可以没有 L1/L2；L3/L4 的来源可直接指向原文，不要求伪造逐层证据链。命中后必须能回到该固定原文，检查现有组包是否支持。
- 大原文只保存在 L0 并不保证普通知识检索覆盖其中细节。导入时按需建立与原文定位绑定的 L1 方法块/概览，保留完整性缺口；用户明确要原文检索时走对应入口。未提取或未索引部分如实报告。
- 语义相似、文档明示关系和经AI解释的间接关联分别表达，不因共同Owner就建立关系。
- 原模型、FTS/向量索引、固定引用与权限模型尽量复用；索引只是可重建投影，不另存一套经验真源。

## 8. 分阶段实施与验收

### A. 收敛语义与入口

盘点根/局部规则、八个Skill、类型策略与公开动作。交付短 work-loop、精简 material-query、兼容入口与按需参考。统一各Owner的“可分层、按内容保存”语义，明确缺层正常；重写强制每轮L1/L2和双文稿要求。保留用户已有显式策略，不无声改变历史对象配置。

对 mode/retain/auto_summary 做使用点审计：当前仅 Research/Project 默认 explore，其余多为basic；确定是保留兼容配置还是最小调整默认，不能只改文案。自动维护、允许保留、必须生成三种含义要分开。没有收益依据不新增“大小研究”状态枚举。

验收：同一个问题不再要求 AI 先选研究/算法问答/工具开发模式；所有命令参考对应真实公开能力；旧入口能找到新入口，不再递归加载两套长流程。

### B. 接通跨对象记录与读取

用隔离样例覆盖核心算法原文、工具源码/经验/Run、项目开发、报告和知识材料。修复真实存在的Owner适配、默认范围、来源展开或记录模式缺口。优先复用接口；确有难用处，增加小型模板/组合调用，内部仍执行既有版本与权限检查，不创建第二写入口。

验收：外来方法未执行仍可保存/找到；无L1/L2的概览与认识可以回原文；工具源码不混入记忆或运行输出；同一Run不重复；来源新修订/撤权时旧理解不会冒充当前可用事实。

### C. 简化持续工作和阅读可见性

连接Owner与RS、简化列出/查看/续接，明确目标与阅读下一步的职责。实现按实际缺口和用户选择的补查决策，保留硬范围/预算和真实意见记录。既有会话原决定保留，不把历史ask_user改写成当时已获授权。

验收：从对象入口找到实际阅读清单，跨进程恢复已读理解和必要细节，不重跑已完成工作；静态导出标明版本；新的自选补查行为有边界测试与实际AI场景。

### D. 清理规则、验证迁移并交付

完整清理冲突引用与重复约束，更新唯一现行定义及实体说明；不把旧手册中的event/map当作现行层级。核心算法准入保持；只统一记录能力，不改变公司关键算法资格。

按影响跑定向回归、公开CLI/HTTP与实际AI场景。若触及Owner发现、Skill安装、目录结构或升级边界，必须运行真实setup扩展旧工作区预览、升级、重复升级和恢复：包括中文/空格路径、工具源码/记忆/runtime、Report/Knowledge旁置memory、RS历史和用户自定义Skill，逐项核对哈希。先保存历史规则和兼容映射，再退休旧入口，不批量移动/改写规范记录。

交付源码与构建资产按现行Windows x64发行规范；本计划不要求新增模型/依赖。无依赖变化则不为流程调整重打模型包，发生变化时按既有离线分发规范另验。

## 9. 有效性验证

固定任务集至少包含：导入未执行算法文档、按用途找到算法、开发小工具、工具处理业务数据并复用经验、失败分析、读取报告/知识中的适用条件、极小查询不建档、跨进程继续原任务。

与当前基线比较：进入任务前读取的规则量、需要切换的Skill数量、记录调用及耗时、重复条目数量、遗漏的关键依据、正确归属、必要细节保留、跨对象命中与固定原文可达性。人工核对来源主张/AI推断/本次验证区分，保留失败例。结构/软件通过与任务质量分别报告；不预先编造数值收益阈值。
