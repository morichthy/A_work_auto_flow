# 三种阅读模式与 note 联想加深

日期：2026-09-17。Owner：PRJ-ARCHITECTURE-EVOLUTION。用户授权：先列计划、建立关键测试、再开发，交付工作台可控制和可保存默认配置的三种模式。

## 行为与边界

- 标准模式 standard：检索 → Owner → 完整文稿 → 研究式 note，保持现行默认行为。允许配置不足时联想；不因低分或检索故障自动宣称缺知识。
- 联想加深 associative：沿同 RS 的具体缺口和已有 note/用户方向，保存实际搜索文本，复用文本召回、Owner 阅读并更新跨 Owner 综合 note。原目标/授权/排除不变；有界轮次，无后台 AI。
- 快速模式 quick：逐条判断实际召回文本是否有用，仅按已交付片段写与标准模式相同质量要求的 note；不自动读取完整文稿，不声称全文覆盖。保存判断与固定片段依据，支持分页续接。
- 新会话从工作区设置读取默认策略。已有 RS/历史 schema 缺字段保持原语义，编辑设置不暗改活动会话。工作台可设置默认策略，并在 RS 内显式切换策略、编辑本次联想文本，采用 CAS/幂等写入。
- Owner 底稿与同 RS 综合 note 不复制规范知识。综合 note 只引用本会话实际交付依据，失效/撤权/超预算均明确报告；note 质量由实际 reader 自查，程序不伪造科学复核。

## 关键验收

- standard 无附加操作仍完整阅读才允许 Owner note；旧 RS 和设置原字节不被读取迁移改写。
- quick 可仅用召回文本形成 note，逐条有用/无用判断可追溯；未交付/未接受/全文越界引用拒绝，固定块定位与覆盖限制到达 handoff。
- associative 使用新的子问题文本而非冒充原问题等义查询；重复操作幂等、轮次耗尽可续接已有笔记，不能重置授权和预算。
- 综合 note 可引用跨已读 Owner 的实际依据；仅列出的引用不等于已读；原底稿/依据变化后旧综合内容不能无提示交付。
- UI 三模式与保存默认设置、当前模式切换和联想文本编辑可用；旧请求晚到不覆盖当前对象草稿。
- 不引入新图数据库/新模型/后台服务；运行端不需要 Node。所有新框架模块进入受控升级清单。
