# 最近问题笔记与证据详情改进

用户要求：工作台和 context 仅在当前入口列出最近24小时更新的阅读问题，按最近更新优先可选择；当前note快速显示；公式正确渲染，正文采用编号引用并可跳转证据详情；证据页面支持标题、整体概览/结论、ID搜索及记录详情、关键上下文、引用和影响关系导航。

## 执行计划

1. 先核对笔记加载、MD渲染、引用和证据检索链路，固定公开接口与保留边界。
2. 建立关键失败测试：24小时边界/顺序/选择隔离、快照读取不触发全库证据核验、过期或撤权提示、公式与编号引用、ID深链、证据搜索/详情/双向导航。
3. 后端实现轻量阅读快照展示与最近问题导航；AI handoff继续重验依据。证据改为轻量搜索加选中记录按需详细加载，避免每次打开遍历并核验全库原件。
4. 前端实现问题选择、快速MD展示、公式与参考文献、可跳转引用及左右栏证据页面；维护已有三模式控制和固定版本信息。
5. 定向后端/前端/真实浏览器、性能实测、构建指纹和真实Windows旧工作区升级恢复；按影响同步文档/Skill/catalog。
6. 保存独立Run、实际验证与限制，刷新索引并校验。保留同分支已有修改与历史固定证据。

## 明确的设计边界

- “最近24小时”按RS内容updated_at计算，查看不延长；非归档、有note、当前可访问，降序排列。当前导航只显示这一窗口；历史RS和修订不删除。
- context保存一个同规则的最近问题导航入口及各RS动态current.md；过期条目退出最近入口，不静默删除历史工作记录。当前问题靠RS身份隔离，不把多个问题合成同一个全局note。
- UI快速读保存的展示快照；快照明确时间/版本与未重新核验证据状态。权限与路径边界不能为加速绕过。AI仍通过reading-handoff得到按当前授权和固定来源核验的context_markdown，不直接盲读磁盘MD。
- 正文编号引用与文末参考文献面向阅读；固定ID、revision、hash和locator保留在引用元数据/详情，不能仅剩不可追溯的编号。未知ID不伪造来源。
- 优先使用既有KaTeX/Markdown依赖；不新增模型、后台AI或图数据库。

初始检查：CurrentReading启动先reading-list，列表对每个RS执行reauthorize，选中后reading-view再核验；这是显示已有note仍慢的明确可疑路径。ResearchMarkdown已集成KaTeX，需用实际常见公式分隔符和引用样例定位渲染问题。当前主Agent消费handoff的context_markdown，而非直接读取context/current.md。
