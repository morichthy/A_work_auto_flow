# 基础检索与召回补齐：实施与验证

2026-09-12；RUN-20260912T021858Z-B6E2DA1386D3。这是软件实现与隔离检索分析，不是科学模型有效性证明。

## 问题、依据与决定

用户要求：“除了高层的检索策略，当前基础（和业界通用）的检索加召回功能完善了吗？如果不完善，在本次开发中也一并补上。”此前暂缓的L1正文覆盖因此进入本轮实施。既有BM25、RRF、来源回读、范围及版本控制可以复用；真正缺口是技术块未进入普通发现、新材料查询未接语义通道，以及多表示挤占窗口。

修改前快照保存在baseline。真实隔离用例将 `zqxbodyonlyneedle` 只放入L1结果块，标题、检索说明和关键词均不含该词；旧版查无结果，失败日志为baseline/body-only.log。初试使用带下划线的英文词组时出现拆词共有项，未能隔离正文变量，已改用单一独有词；没有把该初试算成有效漏检证据。

机制参考：Elastic的[混合检索说明](https://www.elastic.co/docs/solutions/search/hybrid-search)建议融合全文与向量，Qdrant的[混合查询说明](https://qdrant.tech/documentation/search/hybrid-queries/)提供多路融合机制。它们只支撑通用机制，不支撑本工作区性能数字，也不要求安装对应新产品。

选择补齐可重复验证的基础能力：复用现有SQLite、Qdrant local及384维多语言模型，新增确定性技术块投影和有界提供器；保留原规范存储、旧表示和高层研究草案。额外稀疏模型、交叉编码重排、自动图抽取没有本地收益证据，本次不设为必要依赖。AI生成检索背景、初检扩词、多层独立调度和问题上下文持续管理仍由独立Research继续比较；本轮没有假装完成这些高层策略。

## 最终行为

- L1检索说明和稳定正文块都参与FTS/向量发现；标题提供确定性局部背景，不生成新事实。候选仍用简短说明，命中携带固定记录修订、SHA256与块定位，选中后读取完整单元及必要定义。
- 材料查询支持显式 `identity + lexical + dense` 混合召回；默认身份/词法保持兼容，工作台已有能力驱动的向量开关可启用。BM25与余弦分数分别解释，RRF每通道每规范身份只计一次。
- 词法和向量按不同记录截取候选窗口，每记录每通道最多保留四条实际命中诊断，避免多表示/多窗口挤掉另一份材料。过滤不合格候选后，在剩余窗口及预算内补足。
- dense只调用已安装模型。真实tokenizer计量输入，最多512 token；默认一次编码、512输入/总token，不使用输出token。超长、禁止模型调用、缺模型、存储占用、旧向量指纹或水位不完整均明确降级，其他通道保留；不联网补模型。
- technical-blocks v4投影/编码隔离旧索引；旧HEAD相同不代表正文已覆盖。历史词法扫描复用正文块，仍受读取预算并固定旧修订，不把历史正文写入当前向量集合。历史语义全库索引未建立。
- 重建当前26个对象返回 indexed、canonical_writes=0，见workspace-rebuild.json。规范记录、原件、模型文件及依赖锁未改变。新记录照常经公开服务保存，不直接编辑规范存储。

## 真实语义测量

真实安装模型对四个独立合成主题执行英文问题→中文材料查询：电池过充、数据库备份、镜头清洁、湿度灌溉。每题只有一份标为相关，候选页取3，详细语料和断言保存在test_material_dense_real.py及其固定快照。real-model-final.log的独立测量：

| 指标 | 词法 | 混合 |
|---|---:|---:|
| 相关材料召回题数 | 0/4 | 4/4 |
| 首位正确 | 无候选 | 4/4 |
| 每题Top-3精确率 | 不适用 | 1/3 |
| 每题其他主题候选 | 0 | 2 |
| 混合查询活动耗时 | 不比较 | 156–188 ms |
| 混合查询读取/输出 | 不比较 | 10,475字节；898–899字符 |
| 模型调用/输入 | 0 | 1次；15–19 token |

这里 Recall@3 为所需材料是否进入前三，Precision@3 为前三中相关材料占比。每题相关项只有一条，故相关项进入前三时精确率为1/3。首位正确不等于全部返回材料相关；召回后的展开与AI判断仍必要。样本很小且主题差异明显，不能推广为业务相关性达标、跨层策略提速或大库性能证明。测试器没有训练、调参或更换模型。
