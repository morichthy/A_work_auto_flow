# 核心功能与实现逻辑

本页面向使用者和开发 AI，用伪代码与必要说明解释核心功能，保留影响理解的选项、算法和边界。核对日期：2026-09-15（本轮查询计划影响范围），依据当前工作树。细节按各节实现文件读取；完整字段见[文档索引](README.md)，模块关系见 [ARCHITECTURE](../ARCHITECTURE.md)。

相关实现变化时同步维护本页；不在这里展开字段清单、接口参数、存储目录和算法常数，也不加入使用示例。当前没有自动同步文档的后台服务。开发方案还须遵守 [ARCHITECTURE 的稳定设计约束](../ARCHITECTURE.md#稳定设计约束)，不能只凭下列流程决定模块拆分或新增状态。

## 整体功能块、定义与边界

G01–G12 保留原有功能分组身份，描述职责而非十二个独立服务。先用本表理解功能分工，再读后面的流程伪代码；具体模块及变更影响见 [ARCHITECTURE 的模块与变化影响](../ARCHITECTURE.md#模块与变化影响)。完整接口继承关系见 [RUNTIME_STATUS](design/representation-query-v0.2/RUNTIME_STATUS.md)，历史定义不能直接当成当前可调用接口。

| 功能块             | 输入 → 输出                                           | 职责与边界                                                             | 主要实现模块   |
| ------------------ | ------------------------------------------------------ | ---------------------------------------------------------------------- | -------------- |
| G01 固定读取与解析 | 固定引用 → 已核验内容、元数据与缺口                   | 读取指定版本，不把候选清单当成已读正文，不绕过来源授权                 | MQ、MEM、OBJ   |
| G02 内容和修订     | 草案、预期版本 → 新修订或冲突、保存回执               | 校验、幂等提交与历史恢复；单归属对象事务，保存不等于索引或复核成功     | MEM            |
| G03 表示读取与组合 | 固定材料、阅读形式 → 可读内容或缺失原因               | 选择已有正文、摘要或章节形式；模板组合不产生新的语义判断               | MQ、DOC        |
| G04 索引维护       | 已登记内容及变化 → 可搜索投影与覆盖状态               | 重建全文、向量和关系查找辅助；索引不是事实来源，不补造失踪原件         | RET            |
| G05 候选召回       | 问题、范围、用途、来源类型 → 候选与命中依据           | 精确标识、词法及可选本地向量；技术正文块可发现，模型与水位缺口单列     | MQ、RET        |
| G06 去重与排序     | 各通道候选 → 稳定顺序与命中解释                       | 按规范身份去重、RRF 与主题优先排序；排名不代表科学可信度               | RET、MQ        |
| G07 回源和关系导航 | 固定种子、方向与预算 → 关联候选、依据和缺口           | 沿明确内容引用或已采纳关系展开；导航不构成科学支持，不自动发现结构类比 | MQ、RET、EVD   |
| G08 渐进查询       | 查询请求或原游标 → 进度、候选页与停止原因             | 管搜索、续页和取消；保留原范围与累计预算，不把续查当成新查询清零       | MQ、APP        |
| G09 上下文组包     | 已选固定候选 → 正文、必要上下文、补充和缺口           | 补明确依赖并核验用途；不隐式二次搜索，不自动补全整个研究               | MQ、DOC、EVD   |
| G10 阅读视图       | 对象、记录、章节或文稿 → 正文、目录或导出             | 按已编排结构阅读，展示不改版本或证据状态；读取文稿不是生成文稿         | DOC、APP       |
| G11 语义维护       | 新依据、受影响内容、实际审查 → 计划、草案与提交结果   | AI/人判断保留、修订、重组、撤回或暂缓，程序执行；跨对象可能部分完成    | MQ、MEM、GUIDE |
| G12 来源与证据     | 固定内容、用途、适用条件 → 授权、准入、复核与影响结果 | 正式用途逐结论核验；保存、相关性和导航采纳均不能替代复核               | EVD、OBJ、MEM  |
| 共享执行控制       | 预算、实际消耗、取消 → 累计账本与终止原因             | 约束读取、查询、展开和组装；预算字段不表示模型已注册                   | MQ             |

模块简称沿用 ARCHITECTURE：OBJ 对象与来源、MEM 规范版本、DOC 技术内容、EVD 来源与证据、RET 投影与检索、MQ 材料查询、APP 产品入口、GUIDE 规则与说明。表中对应关系用于定位，不表示已实现完全独立的服务边界。

## 功能块怎样衔接

以下箭头表示主要数据交接，不是固定执行顺序；权限、证据与预算检查会贯穿相关步骤。

```text
保存链：
    AI/人组织内容 → G02 保存修订 → G04 更新索引
    → G01 固定回读，分别核对保存和可检索状态

查询链：
    G08 管理本次查询 → G05 召回 → G06 去重排序
    → G01 回源 + G12 资格检查 → 用户/AI 选择
    → 按需 G07 展开 → G03 选择阅读形式 → G09 组包 → G10 阅读

维护链：
    G12 发现来源/证据影响 → G11 实际语义审查
    → G02 保存新修订 → G04 更新投影 → G01/G10 回读

共享执行控制：跨查询、读取、展开与组包累计预算和取消状态
```

变更影响按上表的主要模块进入 [ARCHITECTURE](../ARCHITECTURE.md#模块与变化影响)：在那里查看调用者、数据消费者、状态所有权及应检查的关联模块。CORE 保留功能交接和职责边界，ARCHITECTURE 唯一维护全局模块影响表；两者配合，不用伪代码替代功能定义，也不在此复制第二份架构影响表。

## 1. AI 怎样整理和记录结果

Skill 指导 AI 读什么、如何解释和组织内容；程序负责校验与保存。记录成功不代表解释已经正确。

```text
AI 根据任务读取相应 Skill
    材料导入与整理 → context-maintenance
    各类工作、记录与续接 → work-loop
    新证据引起内容修订 → semantic-maintenance

比较已有对象的目标、概览、成果和未解问题，判断沿用或另建
持续工作维护一份用户可打开的Markdown计划/上下文清单
读取已有对象、当前目标、记录策略和固定证据
    → 核对输入、方法、实际结果、失败与缺口
    → 区分事实、计算、假设和建议
    → 按研究问题组织记录

有用内容按需组合，缺层正常：
    L0：登记原始依据和实际 Run
    L1：写完整技术内容，以及用于检索的简短说明
    L2：写研究经过、选择理由、转折和结果

阶段变化需要整理时：
    L3：提炼有适用条件的经验，区分观察、结论、假设和建议
    L4：更新研究整体概览、限制和未决问题
    文稿：按阅读和交付需要组织章节/文稿，不要求双份

先保存并回读被引用内容，再保存引用它的记录或文稿
```

技术正文按“问题与范围 → 输入与方法 → 公式与计算 → 结果 → 讨论与限制 → 证据与复算”组织，保留变量、单位和固定来源。L1 的检索说明与完整正文块分开；L2–L4 保存可直接阅读的正文和结构化信息。章节与文稿独立于五层记录。已有内容优先复用；简单查阅、纯文档工作不机械补齐全部层级。

方法源：[context-maintenance/SKILL.md](../automation/workflows/context-maintenance/SKILL.md)、[work-loop/SKILL.md](../automation/workflows/work-loop/SKILL.md)、[semantic-maintenance/SKILL.md](../automation/workflows/semantic-maintenance/SKILL.md)。文本要求与校验：[RESEARCH_RECORDING.md](RESEARCH_RECORDING.md)、[memory/contracts.py](../automation/scripts/memory/contracts.py)。

## 2. 结果怎样保存到本地

按需补充：[记录、Run 与索引的实体说明](MEMORY_STORAGE_EXPLAINED.md)——用浮点求和研究解释关键文件、字段、AI与程序分工及可靠性边界；相关接口和功能变更时同次主动维护。

规范记录使用带版本的 JSON，正文使用其中的 Markdown 文本；技术正文可拆成有顺序和依赖关系的块。原始文件保持独立，以固定引用连接。引用包含“对象身份＋版本＋内容指纹”，不会悄悄改指向新版。

```text
AI 将正文、结构化信息、来源和关联组成 JSON 草案
    → 调用公开入口预检
    → 提交草案及预期版本

本地保存服务：
    检查格式、来源和权限
    如果是相同请求的重试 → 返回已有结果
    如果记录已被其他操作修改 → 返回冲突
    如果内容没有变化 → 不制造新修订
    否则：
        在该归属对象下写入新的不可变版本
        校验暂存内容后切换当前版本指针
        保留旧版本与提交回执
        更新检索索引

保存后回读正文、引用和版本，另行检查索引状态
```

规范文件是内容依据，SQLite 全文/关系索引和 Qdrant 向量是可重建的查找辅助。保存使用版本比较防止覆盖、请求身份保证重试幂等、SHA-256 检查内容一致性；提交以单个归属对象为边界。内容已保存但索引失败时补偿索引，不重复创建记录。AI 不直接编辑规范存储文件。

实现：[memory/service.py](../automation/scripts/memory/service.py)、[memory/store.py](../automation/scripts/memory/store.py)、[memory/contracts.py](../automation/scripts/memory/contracts.py)、[memory/index.py](../automation/scripts/memory/index.py)。

## 3. 基础检索与召回怎样运行

AI围绕当前问题使用阅读工作流时，在下述基础检索外组织以下过程：

```text
接续目标、条件、已读理解与尝试结果（已有上下文够用就不重复读取）
需要新依据 → 各层独立多路召回 → 短正文/技术命中块和必要定义，逐条带链接
AI判断直接用途或有具体连接理由的间接启发 → 对保留候选读完整记录
AI实际理解 → 保存压缩理解、连接链、必要细节和待验证处
综合已读材料相关性、缺口与下一步对本地经验的依赖
    → 读深已有依据 / 改写或扩大召回 / 实验或先推进，并更新工作清单与阅读决定
再次扩大召回 → AI按当前失败/方向/成本判断；需要用户取舍才ask_user，已询问须等真实意见
```

此流程复用 G01/G03/G05/G08/G09，由独立阅读工作记录保存状态，不增加知识层。RS显式绑定Owner及可选固定检查点；list/view供对象入口查看最新候选、理解与出处，归档保留历史，导出是标明版本的快照。完整交付只证明程序返回了正文，不保证 AI 理解正确；相似或长链连接仍是待验证启发。手动来源查询维持原默认。调用、持久化与限制见[AI 阅读手册](AI_READING.md)，实现为 [reading.py](../automation/scripts/material_query/reading.py) 与 material-query Skill。

按需补充：[三张索引表如何配合一次查询](MEMORY_STORAGE_EXPLAINED.md#3-索引到底存什么)——包括记录与条目的区别、词项漏检边界和语义查询。

当前“材料查询”通过索引找候选，再回读原记录筛选；不会现场生成答案，也不会临时扫描全部原件。

AI阅读调用在基础查询外增加语言计划：按获准语料选语言，技术/文献问题补英文，保护型号/数值/条件，生成少量等义句；按领域词库每轮尝试同义和单跳关联。词法用紧凑词项、向量用完整语句，各层内按排名融合并保留固定块与查询来源；AI再按正文核对条件。词库关联不是等义或证据，程序保护文本不证明译文正确。实现见[query_plan.py](../automation/scripts/material_query/query_plan.py)，操作见[AI_READING](AI_READING.md)、[QUERY_TERMS](QUERY_TERMS.md)；后面的流程仍说明通用单次材料查询，手动入口不会后台调用AI翻译。

```text
接收问题、关键词、范围和选项
    → 建立查询与累计预算
    → 将用户范围与权限取交集，优先执行排除项
    → 按“内容来源”限定召回类型
    → 按标准对象类型及身份缩小候选目录，默认只取当前修订

如果启用精确标识：按完整规范 ID 查找
如果启用词法：
    合并问题与关键词
    → 分词并扩展配置中的别名
    → 按“任一查询词命中”查全文索引
    → 用 BM25 排序

如果启用本地向量：
    核对本机模型，计量查询输入和调用预算
    → 在所选类型与获准范围内按语义相似度召回
    → 核对每个向量命中的当前条目指纹
    → 模型或索引不可用时报告缺口，保留其他通道

词法和向量均按不同记录截取窗口，避免多个表示挤掉其他材料
技术内容同时索引检索说明和正文块；命中正文携带固定块引用

如果选择所有来源 → 补查已登记文稿、章节、表示与原始登记目录
如果允许旧版 → 有界遍历获准对象的不可变历史，保留版本与未覆盖提示

合并各通道：
    同一身份去重，用 RRF 融合各通道排名
    明确匹配记录主题关键词的候选优先

回读固定版本，检查权限、来源、筛选条件和用途
    不合格项跳过，在剩余窗口和预算内继续补足
    → 返回候选、命中理由、固定引用和缺口

用户选择候选后，可继续翻页、展开或组装正文
```

BM25 衡量文本匹配，RRF 根据各通道排名合并结果；重复命中不会重复抬高排名。词法分词使用中文双字滑窗和英文标识符拆分；可选向量使用已有离线多语言模型。默认仍启用身份/词法，可在高级选项同时开启向量形成混合召回。相关性排名不代表结论可信度；候选预览不是完整技术内容，判断前按任务展开。

| 选项                                     | 实际区别                                                                                           |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 概览与经验／研究经过／技术内容／所有来源 | 分别查 L4/L3、L2、L1 或全部已登记内容种类；不把任意文件当作已登记材料                              |
| 范围与属性筛选                           | 不同维度同时满足，同一维度可匹配多个值之一；“不限”与“没有选择”不同，未知属性是否纳入由选项控制 |
| 探索／审计                               | 可提供未复核候选；审计标签当前不额外触发全面审计                                                   |
| 正式使用                                 | 按填写的适用条件逐条核对结论及证据，只输出符合要求的结论                                           |
| 精确标识／词法                           | 前者匹配完整 ID，后者匹配索引文本；可共同使用                                                      |
| 向量／稀疏／关系召回                     | 向量复用本机标准模型并独立报告水位；稀疏及独立关系召回通道未开放，既有关联导航另走深化入口         |
| 普通文本／短语／布尔语法                 | 当前只开放普通文本；多个关键词不是“必须全部满足”                                                 |
| 仅最新／包含历史／固定本次版本           | 默认只取当前修订，后续更新要求重查；包含历史时显式检索旧修订；固定模式保留本次依据。均不自动换引用 |
| 标准对象类型／具体对象                   | 类型可单选、多选，与对象身份相交；名称或 ID 可进一步缩小结构导航                                   |
| 必要依据读取                             | 工作台默认允许沿已登记依赖跨对象读取，用户可收紧；直接命中仍受筛选限制，排除和来源授权始终有效     |
| 返回数量／预算                           | 前者限制候选页大小，后者限制整个查询的累计处理量；被过滤的内容也可能已产生消耗                     |

翻页、展开和组装沿用同一查询的范围、排除及预算。改变条件须重新查询；取消不清零旧账本。结果只覆盖本次候选窗口，不能由空结果推断全库没有答案。

实现：[MaterialQuery.tsx](../automation/frontend/src/MaterialQuery.tsx)、[material_query/coordinator.py](../automation/scripts/material_query/coordinator.py)、[recall.py](../automation/scripts/material_query/recall.py)、[catalog_search.py](../automation/scripts/material_query/catalog_search.py)、[history_search.py](../automation/scripts/material_query/history_search.py)、[retrieval.py](../automation/scripts/retrieval.py)、[memory/search.py](../automation/scripts/memory/search.py)、[material_query/evidence.py](../automation/scripts/material_query/evidence.py)。

## 4. 关联怎样保存和查找

关联由人、AI 或明确工作流保存；同研究、同关键词或时间相邻不会自动成为固定依赖。三类结构用途不同：

| 结构                 | 保存的含义                                             | 使用位置 |
| -------------------- | ------------------------------------------------------ | -------- |
| 条目中的固定引用列表 | 对应哪些研究经过、技术依据或经验                       | 内容展开 |
| 独立关联记录         | 两端内容、关系类型、采纳状态、共同机制、差异和迁移限制 | 关联补充 |
| 必要依赖             | 阅读当前内容必须知道的记录或技术块                     | 正文组装 |

```text
展开研究经过／技术依据：
    读取所选条目中的相应固定引用列表
    → 核对目标类型、版本、权限和范围
    → 返回可继续选择的候选
    → 工作台同时组装正文、必要上下文与已启用的有效补充
    无可用引用 → 报告缺口，不按同研究猜测

已有关系补充：
    用关系索引找与种子相连的独立关联记录
    → 回读关系及两端固定版本
    → 保留已采纳且仍有效的导航关系
    → 将另一端作为补充候选，去重并限制数量和篇幅
```

内容引用列表不会自动变成独立关联记录。展开允许经验直接指向技术依据；已有关系补充默认查双向邻边，不自动探索全图。关联关闭时不补充，自动结构探索当前未开放。采纳导航关系不等于科学证据支持，端点变化后旧关系需要重新判断。

实现：[material_query/content.py](../automation/scripts/material_query/content.py)、[material_query/associations.py](../automation/scripts/material_query/associations.py)、[memory/index.py](../automation/scripts/memory/index.py)。

## 5. 正文和必要上下文怎样组装

组装依据用户选择和已登记依赖，不由模型临时猜测背景，也不隐式再次搜索。

```text
对每个选中候选：
    核对固定版本、权限和用途
    加入已有正文
    如果声明了必需记录 → 递归加入
        依赖按读取上限和排除核验，不把直接命中的分类误当作依赖上限
    如果只选技术单元的部分块 → 沿块依赖补齐定义
    如果选中独立文稿 → 按已编排的章节与技术引用读取
    固定栅格图示随正文交付并计读取预算，保持各单元自己的图号

按固定身份和定位去重
直接材料优先，关联补充随后
预算不足 → 省略完整块并说明缺口，不截断公式或定义
输出：直接材料＋必要上下文＋关联补充＋固定来源＋缺口
```

只选中部分研究经过时，不会自动补齐该研究的其他经过或全部背景。普通展开引用和导航关系不自动等于必读上下文；后台核验过来源，也不等于已把来源正文加入输出。材料包“完整”只指本次组装没有已报告缺口，不表示整个研究已经覆盖。

实现：[material_query/assembly.py](../automation/scripts/material_query/assembly.py)、[material_query/reader.py](../automation/scripts/material_query/reader.py)、[memory/technical_units.py](../automation/scripts/memory/technical_units.py)。

## 6. 组装、读取文稿和生成研究经过的区别

| 操作              | 做什么                                                   | 是否生成新内容                   |
| ----------------- | -------------------------------------------------------- | -------------------------------- |
| 查询后组装        | 组合所选材料及明确必要依赖，形成临时阅读包               | 不生成新解释或规范记录           |
| 读取研究经过文稿  | 按已有文稿的章节顺序读取固定内容，可选完整过程或精简报告 | 不现场综合所有研究条目           |
| AI/人编写研究经过 | 读取证据，解释路线、原因、转折与结果，明确范围与遗漏     | 显式保存后形成经过记录或独立文稿 |

```text
从查询返回完整文稿：
    用已选命中的明确归属定位已有文稿
    → 合并同一文稿的命中，不按标题猜测同一篇
    → 保留章节、技术块和图示的有序绑定
    → 缺文稿或固定依据不满足时报告缺口，不临时综合

需要新写或更新文稿：
    读已有目录、相关正文和来源变化
    → AI/人实际综合，修改必要章节
    → 保存章节，再更新文稿的固定引用
    → 全文回读，检查衔接、重复、公式、结果和覆盖缺口
```

L2 是过程内容，完整过程与精简报告是独立编排的文稿；保存 L2 不会自动生成整篇报告。来源更新不自动改写旧文稿；缺少精简报告时不会拿完整报告冒充。

实现：[material_query/documents.py](../automation/scripts/material_query/documents.py)、[memory/documents.py](../automation/scripts/memory/documents.py)、[ResearchDocument.tsx](../automation/frontend/src/ResearchDocument.tsx)、[work-loop/SKILL.md](../automation/workflows/work-loop/SKILL.md)。

## 7. 来源变化后怎样维护

```text
发现新版本或反证
    → 定位可能受影响的内容，准备固定阅读材料
    → AI/人实际比较，决定保留、修订、重新综合、撤回或暂缓
    → 预检草案，检查依据是否又发生变化
    → 按归属对象提交并回读，分别检查保存和索引结果
```

维护计划只说明交付了哪些材料，不证明已经理解；没有依赖边时仍可能需要语义审查。旧版本和复核历史保留，跨对象维护可能部分完成。当前没有自动结构发现或自动语义维护代理。

实现：[material_query/maintenance.py](../automation/scripts/material_query/maintenance.py)、[semantic-maintenance/SKILL.md](../automation/workflows/semantic-maintenance/SKILL.md)。
