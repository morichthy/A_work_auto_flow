# 三种阅读模式与 note 联想加深

日期：2026-09-17。Run：RUN-20260916T200528Z-E244B6EE59A3。范围：阅读策略、会话 note、工作区设置、工作台和相关方法文档。本文件为本次开发的完整 Markdown 成果；不改写项目既有技术文稿与历史验收。开发与本次选定验证已完成。

## 实现

| 模式 | 实际流程 | 交给主 Agent 的内容 |
|---|---|---|
| 标准 standard | 检索 → 相关 Owner → 完整文稿 → note | 有实际固定依据的研究式笔记 |
| 联想加深 associative | 根据 note 缺口/线索生成实际子问题，再召回、阅读全文并综合 | 原 Owner 底稿保留，跨 Owner 综合稿优先交接 |
| 快速 quick | 仅对实际召回文本逐条判断有用/无用，以接受片段写 note | 同样保留公式、条件与来源，但明确只有片段覆盖 |

工作区设置保存默认策略、联想开关与最多轮次；新会话采用默认值，已有会话保持原设置。在首页当前阅读及系统记忆的阅读记录中，可显式保存当前会话策略和联想搜索文本。保存控制项本身不启动 AI，实际检索仍由 reader 执行。legacy 历史会话只读展示，不提供不受支持的模式切换。

潜在线索用 exploration_clues 保存内容、联系理由、固定来源、下一查询与限制。阅读/成果整理 Skill 要求关注上下游、变量和迁移条件，区分原文主张、实测及 AI 推断，缺失信息留为未知；不要求无依据地填满关系字段，也不自动建立已验证知识图谱。

## 可靠性边界

- 保持原 mode=owner_document 与 legacy 的兼容身份，策略单独保存。旧设置/会话读取时只在内存补默认，不追写历史。
- quick 判断绑定实际交付片段及指纹；新片段需重新判断，撤回接受使相关旧笔记不可继续当有效依据。切回标准仍须实际阅读全文。
- 综合稿仅接受实际交付正文、已展开来源及接受片段；仅列出引用不算已读。底稿、来源或接受判断变化后提示重新综合。
- 同 RS 保留原目标、授权、排除、累计 Owner 数和预算。版本冲突不覆盖，等待用户/归档状态不可通过切模式绕过。
- note 质量由实际 reader 在同一任务内核对，软件只验证能确定的来源、范围和状态边界；没有新增主 Agent 固定复审环节。
