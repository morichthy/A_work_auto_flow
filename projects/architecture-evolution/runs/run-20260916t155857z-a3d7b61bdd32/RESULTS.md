## 保存策略与根因

- `.local/reading-sessions/<RS-ID>/HEAD.json` 保存目标、笔记、固定来源、授权、预算和请求状态；修订历史仍保留。JSON 为机器状态，正常 AI 使用 `reading-handoff.context_markdown`，不需要加载整份 HEAD。
- 新增 `reading_snapshot.py`，合法 note/decide/view/handoff 后原子生成 `context/reading-notes/<RS-ID>/current.md`。旧会话下一次合法查看补齐；派生写入失败只报告副本失败，不能把已保存的规范状态说成未保存。
- 副本按问题、理解、问题关系、关键细节、限制、下一步和固定出处编排；保留公式与引用，不含字段形式的引用 JSON 或空正文块定位。其独立 30,000 字符窗口不证明主 AI 收到了同样多内容，遗漏明确显示。
- Markdown 不反向更新 JSON、不自动晋升知识，也不自动反映后续撤权；AI 继续工作仍通过公开接口重新授权。副本不进入 Git/公共源码、普通检索或通用全量上下文；升级保留原文件。私人 portable 备份与公开源码不同，本次没有更改其规则。
- 旧列表先对随机 UUID 目录分页再筛选，可能出现无结果首页；现在先按对象/授权/归档筛选，有笔记优先、内容更新时间降序，再分页。只读预算更新不冒充笔记内容更新。
- 旧实现要求宿主与 RS 授权域完全相同，普通本机工作台不能看限定域创建的会话。现在当前可信权限覆盖原域可查看，但请求范围上限仍收紧到原域，较窄域和撤权仍拒绝。

## 工作台行为

1. 首页醒目展示当前笔记。当前标签页中用户选择优先；首次默认最新未归档且有笔记的会话。首页与阅读记录共享选择，同一快照切页不重复获取正文。
2. 阅读记录进入后自动展示；刷新沿用所选会话并读取最新正文，翻页不更换正文。明确区分归属对象（Owner）与问题会话（RS），错误/撤权时撤下旧正文，迟到请求不能覆盖新对象。
3. 默认使用 `reading-view` 的 `notes_only:true`：整个 value（含固定引用）限 30,000 字符，保留覆盖限制，不附整轮检索诊断；仍使用原会话账本。
4. 首页仅保留“查看证据与影响”主入口，默认围绕当前笔记的直接固定引用及一层显式 sources 展开；固定 revision/hash 核对后展示 L0–L4、其他记录及文件/Run 来源。没有关联的层级明确为空，不把同 Owner 的全部记录说成证据。系统记忆链接标明查看当前记录，固定版本正文保留在证据面板。
5. “观察与环境”收进顶部紧凑菜单。材料导航按实际 Owner/记录主题显示中文类别，Run 默认折叠；点击主题定位对应系统记忆，不再展示目录文件名。
