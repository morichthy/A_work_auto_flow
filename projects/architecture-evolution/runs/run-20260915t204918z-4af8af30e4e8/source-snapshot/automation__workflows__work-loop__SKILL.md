# 工作与记录

方法、拆解、阅读范围和验证强度由 AI 根据任务判断。用户指定优先；这是一套记录协议，不要求先选择研究或开发模式。

用 `memory list-owners`/`inspect` 找候选Owner，比较其目标、概览、已有成果和未解问题：本次是同一目标的继续或子任务就沿用；仅主题相似则引用，独立交付目标才另建。用户指定优先，目录名不是判断依据；持续任务用 `memory resume` 读必要目标与下一步。工具用于业务数据时，Run通常归业务对象；通用工具经验以固定引用归工具。源码、记忆和运行输出分开。

持续或多步工作维护一份用户可打开的Markdown工作上下文清单，优先复用本任务计划。记录目标/条件、当前与召回材料的链接和阅读状态、理解/经验及必要细节、尝试/缺口、下一步与补查理由；无RS也维护。重要材料、结果或方向变化及交接时更新，不逐条抄日志。首次建立和交接给出链接；位置与续接见公共动作参考。

需要本地依据时使用 material-query。保留候选后完整阅读，记录理解、连接、必要细节和出处；已有依据足够就推进，不为每条消息重复搜索。阅读会话绑定本次Owner；`material-query reading-list --owner ID` 与 `material-query reading-view --session RS-ID --markdown`可查看。

独立执行建立 Run，Python等脚本用 `run-execute`，其他工具或已有产物用 `run-register`。保存真实输入版本、结果与失败；无执行的分析可直接记录，不虚构Run。重要配置变化、关键反例等即使很短也值得留存。

有用内容按职责保存：L0原始依据、L1完整方法/分析、L2有依据的经过、L3可复用认识、L4介绍或阶段概览。缺层正常，不补空条目，不重复正文。原文步骤可作L1，文献记载的经过可作L2；注明来源叙述、AI推断或本次观察，不把原文主张当成亲自验证。总之可以适当扩展L0-L4的定义，使得当前的工作流中有价值的内容通过分级记录下来。

对话中产生有用中间内容即可自主保存并提交，无需等用户逐次要求；未复核认识保留其状态，待同步影响写入当前工作清单。用户要求记录重要结论/当前成果、阶段总结或交接，以及AI发现结果、反例、适用范围或方向实质变化时，调用 [整理更新当前成果](../consolidate-results/SKILL.md)：先完整读取当前概览与文稿，盘点上次文稿以来的相关记录变化，再维护内容、概览、章节和文稿根，全文回读并核对上下文。每次普通commit不强制收口；用户明确只暂存或限定范围时遵从。只有完成该Skill的实际检查才标明“本阶段完整成果已同步”，不能把局部保存当作整体同步。

用公共 `memory validate-draft`/`commit` 提交并固定回读，分别检查保存和索引状态；INDEX_PENDING时补索引，不另建副本。交接时保存结果、依据、未解问题和可执行下一步；Owner检查点是工作交接，RS只管阅读。文稿按实际阅读/交付需要编排，不要求每任务双文稿。

自主推进已授权工作；依据不足时结合材料相关性与下一步对本地经验的依赖，判断推进、读深已有依据、改写/扩大召回或换验证方法，并记下理由；具体按material-query。不按次数强迫中断，方向、成本或权限需要用户决定才询问。反馈给出结果与可打开记录链接，未知事实和验证范围明确保留。

首次调用不熟悉的接口时按需读[公共动作参考](../../../docs/WORKFLOW_ACTIONS.md)，不必全文加载。公司算法准入/文档核对见[专项参考](references/core-algorithms.md)；开发采用development-checks的影响检查。不要把专项参考变成所有任务的必经步骤。
