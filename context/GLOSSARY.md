# 术语表

| 术语 | 定义 | 注意事项 |
|---|---|---|
| 数据卡（Data Card） | 对数据来源、含义、组成、限制、责任与推荐用途的说明 | 回答“这是什么、能否用” |
| 数据契约（Data Contract） | 对 schema、单位、质量、兼容性、SLA 与敏感等级的机器可读约束 | 回答“必须满足什么” |
| 核心算法 | 公司算法/模块文档定义的关键模型算法，具有工程目标、模型方法、接口与适用边界，可通过子系统协同实现 | 不等同于脚本函数、软件模块或通用工具 |
| 核心算法卡（Core Algorithm Card） | 上述算法项的文档来源、接口、方程、假设、V&V/UQ 与失效模式说明 | module.json、MOD-ID 和 --module 等沿用兼容字段名，只指核心算法 |
| Run | 一次不可混淆的分析、仿真、标定、训练、诊断或报告生成实例 | 回答“这一次发生了什么” |
| Verification | 验证实现是否正确求解了预期方程或逻辑 | “方程解对了吗” |
| Validation | 验证模型在目标现实条件下是否足够有效 | “方程代表现实吗” |
| UQ | Uncertainty Quantification，不确定度识别、传播和汇总 | 必须标注来源与置信含义 |
| 血缘（Lineage） | 实体、活动与执行者之间的使用、生成、派生和归属关系 | 可对齐 W3C PROV/OpenLineage |
| ADR | Architecture/Algorithm Decision Record，重要技术决策记录 | 旧决策不删除，标记被替代 |
| 候选记忆 | AI 或人工尚未复核的总结、提示和经验 | 不能覆盖正式事实源 |
| 正式知识 | 有来源、适用范围、验证状态和责任人的版本化内容 | 可用于后续决策 |
| 控制平面 | 当前工作区内的小型元数据、代码、契约、计划和知识 | 应可版本化与检索 |
| 数据平面 | 共享盘、数据库、计算平台中的大数据和大产物 | 通过引用和指纹连接 |

添加术语时避免只写缩写；若不同团队用词冲突，应保留别名和适用域。

## 检索与组织术语

| 术语 | 定义 |
|---|---|
| Project | 可选目标/交付视图，不拥有算法副本 |
| Research | 独立问题与证据集合，可关联多个核心算法和 Run |
| Owner | 可独立拥有规范记录或 Run 的稳定归属对象，包括 Research、Project、核心算法、数据、工具、知识和报告；一条记录只有一个 Owner，关联可以多值但不复制归属 |
| L0 原始材料 | Run 输入/产物、脚本、日志和获准来源的统一追溯视图，不表示再复制原数据 |
| L1 技术单元（detail） | 实验、方法、推导或分析；检索说明与稳定完整正文块分开；只有实验必须有 Run |
| L2 研究经过（narrative） | 有上下文的研究、实施、使用、排错或决策经过，说明背景、实际尝试、选择理由、转折、结果和限制 |
| L3 可复用认识（experience） | 可迁移的观察、结论、假设或建议，须说明证据、适用条件和不适用边界 |
| L4 整体概览（overview） | Owner 的顶层发现入口，概括用途、范围、当前结果或状态、限制和未决问题；短经验可只有一条自足 L4 |
| 章节（document_section） | 组织固定技术块、必要定义与衔接的独立记录，level=null |
| 研究文稿（document） | 完整研究过程 research_process 或精简研究报告 research_report；共享固定依据，各自维护结构，level=null |
| 文稿影响提示 | 对来源新修订、新技术单元或变化关注的局部检查候选；不自动修正文稿或替换证据 |
| 模块影响图 | 框架模块变化后需要复查哪些模块和文档的维护图；不是公司核心算法图或自动验证机制 |
| Embedding | 成熟模型将文本映射成数值向量，无需先训练 |
| Qdrant local | 本地持久化向量检索库，当前单进程使用，无 HTTP 服务 |
| RAG | 检索相关资料，供生成模型依据资料回答的工作方式；不是单独的模型 |
| 全文 / 片段 | 上下文装载单位，与向量索引切片单位不同 |
| OCR | 从图片提取文字，不能代替对图表含义的理解 |
| 上下文调查 CTX | 一次带阶段、选择、预算、来源指纹的阅读记录；后续扩展指向父 CTX |
| Q 查询 | 一次检索候选快照，可有单份来源反馈 |
| QMEM / PKT | 规范记忆查询与材料包的身份；不与旧材料 Q/CTX/CF 回执混用 |
| RS（Reading Session） | 围绕一个问题保存范围、预算、阅读进度、判断、笔记和固定来源的会话状态；不是规范知识、Run 或文稿 |
| `owner_document` | RS 的按对象完整阅读处理模式：候选按 Owner 组织，相关 Owner 进入当前可读完整正文；不是文稿类型或阅读策略 |
| `legacy` 阅读模式 | 缺少新模式字段的旧 RS 所采用的兼容处理方式，按候选记录阅读和笔记并沿用跨操作累计预算 |
| 阅读策略（strategy） | `owner_document` 内部的 `standard`、`associative` 或 `quick`；决定是否完整阅读及是否受限补查，不改变 RS 的处理模式 |
| reading note | RS 内保存的材料理解、关键细节、限制和固定出处，用于续接；不会自动成为规范记录或已复核结论 |
| Owner 发现投影（discovery projection） | 从 Owner 元数据、L4/L3、L2 紧凑内容和 L1 检索说明派生的可重建检索索引；与全文索引分离，不替代正文、证据或复核 |
| 固定引用（FixedRef） | 由对象身份、版本、内容指纹和可选定位组成的引用；目标更新后不会静默漂移到新版 |
| 直接范围（scope）/依赖上限（scope_ceiling） | `scope` 限定直接召回对象，`scope_ceiling` 限定读取已声明必要依据时可达到的授权范围；二者都不能扩大原有授权 |
| 互补筛选包（screening packet） | 为判断一个 Owner 是否相关而交付的少量互补命中窗口及来源信息；不是完整正文或已读文稿 |
| brief | 从长 Run 选择原始字段的摘录，不是模型生成的新结论 |
| 一致性差异 | 文档和代码可能不同的线索；需核对版本与行为，不自动判定哪方错误 |

层级、技术块和文稿的完整定义集中在[研究记录标准](../docs/RESEARCH_RECORDING.md)，当前字段以适用的 schema/contracts 为准；旧版本按兼容语义读取，不修改历史字节。
