# AI 研发工作区

用于整理算法文档、代码、实验和研究知识的 Windows 本地工作区。用固定版本、来源和复核记录连接“已有材料 → 分析/实验 → 可复用知识 → 报告”，支持 AI 辅助查询、整理和继续研究。

## 能做什么

- 登记已有资料及文档—代码版本关系，按授权范围检索和回读原件。
- 用 Run 保存实际输入、程序、输出、失败和限制；通过版本记忆保留技术内容与修订历史。
- 按概览与经验、研究经过、技术内容查找已有正文；技术块支持词法与可选本地向量召回，选择固定候选并沿明确关联展开。
- 统一 `$work-loop` 负责需要归属、记录与续接的工作；持续工作维护可打开的Markdown上下文清单，集中展示目标、材料、必要细节和下一步，位置与维护见[公共动作](docs/WORKFLOW_ACTIONS.md#用户可见的工作上下文清单)。查询当前源码、配置、默认参数或命令状态时直接检查目标文件，不启动阅读流程或建档；需要跨研发材料/经验搜索和完整阅读时才调用 `$material-query`。
- AI 可围绕同一问题建立阅读会话：standard/associative 在多路召回后选择Owner并逐篇读完整文稿，associative 只在不足时按主Agent给定的联想问题受限补查；quick 逐条判断实际召回片段，明确不代表全文覆盖。note 只承载有用的材料知识、条件、经验和局限，任务编排单独保存。工作台首页“当前阅读笔记”可选择最近24小时更新的问题并控制阅读模式，引用跳转到“证据与影响”；系统记忆不再重复提供阅读记录页。人类可读副本位于 `context/reading-notes/<RS-ID>/current.md`，程序状态仍由 `.local/reading-sessions/` 管理。副本不是新的知识记录，使用当前来源须经接口重验。见 [AI 阅读](docs/AI_READING.md)。
- 用技术单元和独立章节组织完整研究过程、精简研究报告；查看来源变化及待维护内容。
- AI 可自主保存有用中间记录；记录重要成果、阶段总结/交接或实质变化时，用 `$consolidate-results`（整理更新当前成果）完整阅读概览与文稿，盘点上次文稿以来的变化，维护全文与上下文一致性。只有实际检查完成才声明本范围已同步，无后台自动写作。
- 查看材料关系、结论复核与报告影响；显式开启监测后产生观察和维护候选。
- 用新版源码及配套依赖包升级旧工作区，保留业务资料、用户配置与恢复依据。

文件存在、已登记、固定版本可读、索引覆盖和结论已复核是不同状态。保存不会自动完成研究综合，索引成功也不证明结论正确。各对象新建/修订的每条 L0–L4 都须从自身背景与正文独立读懂问题、条件、关键内容、结果和限制；AI 逐条回读检查，不靠聊天或文稿补齐前提。详见[记录标准](docs/RESEARCH_RECORDING.md#每条记录必须独立可读可以正确复用)。

## 先理解几个概念

| 概念 | 用途 |
|---|---|
| 核心算法 | 公司算法/模块文档定义的关键模型算法；普通脚本或框架软件模块不因此成为核心算法 |
| Research / Project | Research 围绕研究问题组织内容；Project 聚合交付目标与关联对象，默认复用同一分层记录标准 |
| Run | 一次实际分析/执行的输入、输出和可复现依据；优先保存到开展工作的对象内 |
| L0–L4 | 所有Owner共用的内容压缩、发现和展开层级：L0原始材料追溯；L1完整技术/方法/分析单元；L2研究、实施、使用、排错或决策经过；L3区分观察、结论、假设、建议的经验；L4顶层发现概览。层级不是可信等级，短经验可只有L4全文 |
| 技术单元与文稿 | L1 含检索说明和完整技术块；章节固定引用块，可按需要组织完整过程或精简报告，`level=null` |
| 版本记忆 | 在已有对象上保存规范内容、来源、旧修订与回执；“规范”表示管理方式，不表示已验证 |
| 表示与材料包 | 表示是阅读/组合规则；材料包是本次实际选出并展开的固定内容，不是另一份规范存储 |

完整概念、核心调用与算法、关联和上下文结构、Skill 解析顺序及本地保存机制见 [CORE](docs/CORE.md)，随相关实现同次维护；完整字段和记录要求见 [研究记录标准](docs/RESEARCH_RECORDING.md)。

## 安装、打开与升级

新源码解压后执行：

```powershell
.\setup.cmd --register --open
```

配套 `dependencies-windows-x64.zip` 与 `.zip.sha256` 放在 setup.cmd 旁自动识别并离线核验；无配套包时首次完整安装需要联网下载。基础功能可用 `--profile core`，它不代表完整模型环境。

打开已有工作区用 `workbench.cmd`，注册后新终端也可用 `rdwork`。体验合成示例用 `workbench.cmd workbench --demo`，数据位于独立 `.local/test-workspace/`。使用端无需 Node。持续监测须显式开启，关闭浏览器不等于停止 Python 服务。

系统记忆默认进入“研究经过”，随后为“对象记忆”和“关联导航”；对象记忆需主动点击生成。当前标签页内切换功能会保留已读取结果、选择与草稿，刷新浏览器后重新开始。证据页在搜索和选择条目后按需读取详情；监测范围限定 Owner 记录，不扫描发布依赖 ZIP。

升级时关闭旧工作区的工作台、索引和实验进程，从**独立的新版源码目录**执行：

```powershell
.\setup.cmd --target "D:\研发\旧工作区" --register --open
```

新旧目录不得嵌套，升级后继续使用旧目录。源码、配套依赖 ZIP 与校验文件一起交付，用户无需逐包安装。可加 `--preview` 预览；框架和依赖分别用 `--rollback`、`--rollback-dependencies` 恢复，指纹检查拒绝覆盖后续新修改。

仅提供源码不会自动替换旧模型；模型更新必须配匹配依赖包。当前自动迁移限标准名称、路径和兼容 384 维。安装/恢复见 [SETUP_WORKBENCH](docs/SETUP_WORKBENCH.md)，打包与发布见 [DEPENDENCY_RELEASE](docs/DEPENDENCY_RELEASE.md)，离线迁移见 [WINDOWS_PORTABILITY](docs/WINDOWS_PORTABILITY.md)。

## 日常怎样用、怎样融入已有知识

AI阅读可在多路召回后，对固定正文和必要定义使用离线Cross-encoder及显式条件特征重排，保留原排名、依据与费用。新阅读模板出厂默认auto，模型不可用时报告回退；旧会话保持原策略。详细选项、适用边界与真实效果评测方法见[AI_READING](docs/AI_READING.md)。模型随配套离线依赖包安装，运行不会自动联网下载。

工作台侧栏“工作区设置”可调整子Agent协作开关、默认阅读模式、联想开关/轮次、默认查询数量、AI阅读最多Owner数、最终note估算token、重排模式和候选池；单次操作资源保护放在高级设置。最近阅读问题只展示24小时内可访问的有note会话；历史不删除，静态recent副本仅在保存或打开recent接口时刷新，没有后台时钟任务。用法与生效边界见[工作区设置](docs/WORKSPACE_SETTINGS.md)。

材料阅读优先由宿主独立低成本reader完成检索、全文阅读和reading note，主Agent只接收有界笔记、必要细节与固定出处。关闭协作或宿主不支持时沿同一会话独立执行；任务包不等于已经派工。见[阅读交接](docs/AI_READING.md#子-agent-阅读与主-agent-交接)。

工作台“工作区设置”可填写子Agent能力/模型要求，默认较低能力、低成本和低推理深度。程序默认值随源码发布；保存后的根目录`workspace-settings.json`属于本地用户配置，Git忽略且升级保留。详见[设置说明](docs/WORKSPACE_SETTINGS.md)。

| 要做的事 | 操作与维护方式 |
|---|---|
| 导入已有资料 | 提供路径、用途、允许范围，调用 `$context-maintenance`。AI 关联已有算法/研究、登记来源与版本；原件留在获批位置，保存引用和小型受控证据。缺少稳定 ID 的知识文档可显式采用，原正文不改 |
| 查材料或理解算法 | 默认工作入口 `$work-loop`；按内容来源查已有正文用 `$material-query` 或工作台“材料查询”。先看范围/可用性，选固定候选，再组包并检查缺口 |
| 开展研究/实验 | 用 `$work-loop`；新 Python 实验可 `run-execute`，已有产物可 `run-register`。登记后 L0 自动投影；技术内容由 AI/人编写，实验型单元绑定真实 Run |
| 形成报告 | 从固定技术块组织章节、完整过程与精简报告；更新结构和必要定义，来源新修订不会自动替换旧引用 |
| 查关联或启发 | 工作台“材料关系”浏览；`$association-exploration` 比较跨领域结构、差异和适用边界。导航采纳不等于科学支持 |
| 纠错与继续 | 保存目标/检查点，用固定版本恢复上下文；`$semantic-maintenance` 审查新反证和来源变化，决定保留/修订/撤回并回读，保留旧版 |
| 查看依据和监测 | 用 `$evidence-inspection` 或证据/监测页；观察只产生候选，结论复核单独记录 |
| 开发框架 | 用 `$development-checks` 阅读现行文档、按风险验证，并完成文档维护闭环 |

材料查询先按 Research、Project、Knowledge、Run 等标准类型筛选对象，支持多选和名称查找。内容默认查“概览与经验”（L4/L3），也可选“研究经过”（L2）、“技术内容”（L1）或“所有来源”（包含已登记文稿、章节、来源和 Run）。默认查当前修订；显式允许历史后，旧命中保留版本标记和原固定引用。

选中候选后，上方操作区可组装、展开研究经过/技术内容、深化，或“返回完整文稿”。完整文稿按所属文稿去重，按原章节次序呈现正文及受控图表。展开沿作者固定关联，缺少正文、来源或关联时显示缺口。默认允许读取所选材料引用的获准必要依据（可跨对象），高级选项可收紧；直接候选仍受所选范围限制，显式排除和来源授权始终有效。同一查询累计计量，默认活动执行时间5分钟、读取16 MiB、输出80,000字符，阅读页面的等待时间不计入执行预算。用法见[材料查询](docs/MATERIAL_QUERY.md)。

旧事件和地图须实际整理正文、保存新修订并更新索引，才进入新经过/概览；迁移方法见[记忆使用指南](docs/MEMORY_USAGE.md)。材料查询支持身份、词法、可选本地向量及既有关联导航，自动结构发现与生成式模型代理尚未注册。

AI阅读入口支持按语料生成少量中英等义查询，技术/文献问题补英文，紧凑词法与完整向量分路召回并融合。日常在 [retrieval/query-terms.json](retrieval/query-terms.json) 维护中英术语、别名与单跳关联词；每轮按领域使用并记录词库指纹。程序不自动翻译或认定候选满足型号/数值条件，AI按固定正文核对。用法见[AI阅读](docs/AI_READING.md)与[词库维护](docs/QUERY_TERMS.md)。

默认 AI 阅读先查询独立的 Owner 压缩发现索引：它只投影 L4/L3、L2 紧凑内容、L1 检索说明和 Owner 元数据，按路线融合 Owner 后交付少量互补筛选窗口，再完整阅读被判断为相关的 Owner。它不复用全文索引的层级过滤；发现不可用、覆盖不完整或结果不足时，只在用户明确选择后才执行全文补偿召回。旧 legacy 会话和 quick 片段阅读保持原边界。当前实现、入口、升级验证与仍未开展的检索效果评估见[详细设计](docs/design/OWNER_DISCOVERY_RETRIEVAL.md)与[开发计划](projects/architecture-evolution/plans/owner-discovery-retrieval-20260918.md)。

保存返回 `INDEX_PENDING` 时可能正文已保存，应固定回读并用 `memory reconcile` 补偿，避免重复创建。索引重建不能补回失踪原件；原件搬迁需要明确来源映射。新知识先以来源和适用边界保存，经适用复核再复用，不静默删除冲突或旧结论。

操作详情从[文档索引](docs/README.md)查材料导入、Run、记忆、检索、证据和查询手册。所有 CLI 命令可用 `--help`：

```powershell
.\workbench.cmd doctor
.\workbench.cmd material-query --help
.\workbench.cmd memory --help
.\workbench.cmd index-knowledge --dry-run
.\workbench.cmd refresh-index
.\workbench.cmd validate
```

## 目录如何维护

| 位置 | 保存什么、由谁维护 |
|---|---|
| `core-algorithms/` | 公司核心算法卡、来源、实现版本与适用域；变更时检查固定依据 |
| `research/`、`projects/` | 研究/交付目标、计划、技术内容与所属 Run；引用已有知识，避免平行副本 |
| `runs/` / 对象内 `runs/` | 根目录兼容无归属轻任务/历史；新 Run 优先对象内，失败与回执保留 |
| `knowledge/`、`reports/` | 经验/决策及报告产物；维护来源、复核和引用版本 |
| `data/`、`tools/` | 数据卡/契约与可复用工具登记；大数据保留在获准存储 |
| 对象内或旁置 `memory_home` | 服务维护 owner、commits、HEAD 和事务回执；通过 CLI/工作台修改，勿手改指纹 |
| `retrieval/`、`context/` | 来源/检索配置、导航和当前状态；`context/reading-notes/` 为私人阅读上下文 Markdown 副本，不分发、不自动作为新知识检索 |
| `automation/`、`.agents/skills/` | 程序、前端、测试和方法源；Skill 发现入口链接 workflows，避免规则双写 |
| `docs/` | 稳定的现行说明与按类保留的历史；详细入口和分类只从 docs/README 进入 |
| `services/qdrant/`、`.local/` | 本机运行环境、索引/临时状态、演示及备份；由部署/服务管理，不公开业务内容 |
| `inbox/`、`archive/`、`governance/` | 待整理材料、冷存档及授权/数据边界；归档不抹掉固定引用 |

## 开发与已知边界

测试点按功能行为、失败边界和真实故障持续补充；固定基线及逐项风险依据统一维护在 [catalog](automation/testing/catalog.json)，准入、复审与退出见 [测试规范](docs/TESTING.md)。新增登记不会自动进入基线，基线存在也不要求每次小改动全部运行。

讨论全局方案前完整读、局部方案按相关决定读 [开发决策与演进记录](docs/DEVELOPMENT_HISTORY.md)，了解选择理由、历史错误和未决讨论；开发后补实际结果与新教训，详细证据按链接追溯。

开发按Skill列出的影响范围维护六份核心文档；全局整合、发布或明确要求全审时前后完整阅读。当前技术框架/影响表只维护在 [ARCHITECTURE](ARCHITECTURE.md)，功能定义在 [CORE](docs/CORE.md)。任务计划、历史决定和实际验证留在所属 Project/Run，规则见 [文档维护](docs/DOCUMENTATION_MAINTENANCE.md)与[测试选择](docs/TESTING.md)。

开发按development-checks选择受影响文档、Skill和验证；全局工作流整合、发布或明确要求全审时完整核对六文档与所有入口。默认8项活跃Skill，旧research-loop/workspace-context已退休，改用work-loop；工作、记录和续接统一由work-loop负责，阶段成果一致性用consolidate-results，格式质量按成品技能处理。见[工作流入口](automation/workflows/README.md)。

当前由 memory-v4 聚合契约兼容 v1–v3 固定版本；新经过/概览及分类经验使用 v4，L0/L1 与独立文稿不变；材料查询接口另为 v0.2。旧材料检索、规范记忆检索与新材料查询应用并存，Qdrant local 有进程排他限制。软件回归不证明检索质量、实际 AI/人工认可或科学结论。当前任务与已知缺口见 [NOW](context/NOW.md)，历史质量未通过、万条规模暂缓和第二物理机待验收分别保留。

公共源码包含程序、规则、模板、可复用合成测试与预构建资源；`git archive` 排除研究/Project/核心算法/Run 实例、运行环境和业务记录。完整 checkout 中保留浮点求和研究例子；私人 portable 快照不是公共发行包。发布前检查实际文件边界，参见[依赖分发手册](docs/DEPENDENCY_RELEASE.md)。
